# Lec 5 创造力与概念生成（Creativity and Concept Generation）

> 对应Spring 2026 Class 6。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；核心阅读：[PDD第8版](https://www.mheducation.com/highered/product/Product-Design-and-Development-Ulrich.html)第7章。

## TL;DR

- 概念生成先扩大解空间，再比较候选方案；过早评价会让团队围绕最先出现、最熟悉的点子收敛。
- 功能分解把整体任务拆成子功能，内外部检索为每个子功能寻找工作原理，再通过组合形成系统概念。
- Sprint 2要求每位成员至少提出两个概念，并用草模、关键需求覆盖和客户反馈推动概念从数量走向质量。

## 一个可审查的生成过程

1. 澄清问题和关键客户需要，避免把暂定规格误当成唯一解法。
2. 用黑箱模型描述输入、输出与必要转换，再分解关键子功能。
3. 在团队经验、竞品、专利、专家和相邻行业中检索可用原理。
4. 为子功能建立候选方案，并组合成多种完整概念。
5. 用草图、短说明和草模把隐含假设外化。
6. 反思搜索是否被既有产品形态或成员专长限制。

::: definition [产品概念]
产品概念是对产品形态、功能和工作原理的近似描述，足以让团队讨论它如何满足需要、哪些部分仍不确定，但尚不等同于详细设计。
:::

::: pitfall [把功能分解当零件分解]
“电机、齿轮、外壳”已经是某种架构；“储能、传递扭矩、保护使用者”才是可由不同原理实现的功能。用零件名分解会把当前方案偷偷写进问题。
:::

::: insight [概念数量是手段，不是绩效]
要求每人提出两个以上概念，是为了打破团队对第一个可行方案的依赖。真正的质量指标是候选概念是否覆盖不同工作原理，以及比较后能否指出哪些子方案值得重新组合。
:::
