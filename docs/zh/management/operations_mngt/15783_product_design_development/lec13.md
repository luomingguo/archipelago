# Lec 13 用户体验设计（User Experience Design）

> 对应Spring 2026 Class 15。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；大纲指定阅读为Maven的六项UX原则概览。

## TL;DR

- 用户体验设计关注人如何理解状态、采取行动、获得反馈、恢复错误并完成目标，范围不限于数字界面的视觉样式。
- 一致性、可见反馈、清晰层级、容错和可达性必须落实到具体任务与状态，不能只作为抽象原则打分。
- Sprint 3的工作模型应让用户执行关键任务并暴露不确定性；可用性证据应记录行为、结果和障碍，而非只收集喜好。

## 从任务到状态

先定义目标用户、关键任务、进入条件和成功结果，再列出用户可能经历的状态：未开始、进行中、成功、空状态、权限不足、输入错误、系统失败和恢复。界面需要在每个状态提供与风险相称的反馈和下一步。

::: definition [可用性]
可用性描述特定用户在特定情境下完成特定目标的有效性、效率与满意度。它不是产品的一项固定美学属性，而是任务、用户和环境共同决定的结果。
:::

## 评审问题

- 用户是否知道当前状态和可执行动作？
- 控件的结果是否可预测，反馈是否及时？
- 重要概念、术语和模式是否一致？
- 错误能否预防，发生后能否理解并恢复？
- 不同能力、设备和环境下是否仍可完成核心任务？

::: pitfall [只问“喜欢吗”]
偏好回答不能证明用户能否发现入口、理解状态或完成任务。测试应给出情境和目标，观察实际行为，并把引导、错误与完成时间分开记录。
:::

::: insight [必要摩擦也属于好体验]
危险、昂贵或不可逆的操作需要确认、解释和撤销边界。体验优化不是消灭所有步骤，而是减少无信息价值的负担，同时保留帮助用户理解后果的摩擦。
:::
