# Lec 4 敏捷开发过程（Agile Development Process）

> 对应Spring 2026 Class 5。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；核心阅读：[PDD第8版](https://www.mheducation.com/highered/product/Product-Design-and-Development-Ulrich.html)第19章。

## TL;DR

- 课程把项目组织为五个两周冲刺，每轮包含目标、规划、待办、日常协调、演示、评审和复盘，以稳定节奏推进跨学科工作。
- 硬件敏捷不能假装所有变化都没有成本；长交期采购、工装和实体集成必须提前暴露，同时把可逆的不确定部分留给迭代。
- 演示检验产品增量，评审检验方向与待办，复盘检验团队过程；三者对象不同，不能合并成一次进度汇报。

## 冲刺的基本闭环

每个冲刺从一个清晰目标和规划会议开始，团队把完成目标所需工作组织进待办，并在执行中持续协调。冲刺末通过可观察的模型、研究结果或分析进行演示，邀请利益相关者评审，随后单独复盘协作方式。

::: definition [冲刺目标]
冲刺目标描述两周结束时团队希望获得的产品能力或关键证据。它不是任务清单；即使具体任务变化，只要仍能达成目标，团队就可以调整路径。
:::

## 课程中的五轮节奏

| 冲刺 | 核心目标 |
| --- | --- |
| 1 | 使命陈述与客户需求分析 |
| 2 | 概念探索、概念验证模型与报告1 |
| 3 | 初始工作模型与详细设计 |
| 4 | 精炼模型、专利评审与生命周期评估 |
| 5 | Alpha原型、商业论证、报告2与最终展示 |

::: pitfall [把敏捷理解为不做计划]
实体产品的材料、供应商、设备和制作窗口存在真实提前期。敏捷要求根据证据滚动更新计划，并不取消架构判断、采购承诺或集成节点。
:::

::: insight [用风险排序待办]
待办的优先级不应只由任务可见度或个人偏好决定。先处理“若失败会让整个方向失效”的假设，往往比先完成最容易展示的外观工作更能节省总时间。
:::
