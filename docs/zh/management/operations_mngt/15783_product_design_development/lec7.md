# Lec 7 产品规格（Product Specifications）

> 对应Spring 2026 Class 8。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；核心阅读：[PDD第8版](https://www.mheducation.com/highered/product/Product-Design-and-Development-Ulrich.html)第6章。

## TL;DR

- 客户需要表达期望结果，产品规格用“指标、数值、单位和测试条件”把结果变成可验证目标；两者必须保持多对多追溯。
- 目标规格在概念探索期界定方向，最终规格要根据选定概念、技术验证和权衡更新，不能把早期数字当永久承诺。
- Sprint 2只要求为3–4项关键需要制定并论证目标规格，Sprint 3再说明最重要功能规格如何来自需求与竞品基准。

## 从需要到指标

“携带方便”是客户需要，“总质量不超过1.5 kg”是规格。需要不应被数字替代，规格也不能停留在形容词。团队应建立需求—指标矩阵，检查重要需要是否至少有可测试指标支撑，以及每个指标是否服务真实需要。

::: definition [产品规格]
产品规格是对产品应实现性能的精确描述，至少包含指标、目标值、单位和适用测试条件。它描述可观察结果，不应无必要地锁定实现方案。
:::

## 建立目标规格

1. 根据关键需要列出直接、可测的指标。
2. 建立需求—指标关系，识别遗漏与冲突。
3. 用统一方法测量竞品，区分实测数据与营销宣称。
4. 为指标给出边际可接受值和理想值。
5. 记录目标依据、测试条件和当前不确定性。

::: pitfall [虚假精确]
早期目标若写出很多小数位，却没有样本、测试方法或竞品证据，只会把猜测伪装成工程事实。精度应与证据强度匹配。
:::

::: insight [规格是跨职能合同]
好的规格让用户价值、工程实现和测试方法在同一条记录中相遇。若市场团队说“更轻”、工程团队说“换材料”、测试团队却不知道如何判定成功，说明合同仍未建立。
:::
