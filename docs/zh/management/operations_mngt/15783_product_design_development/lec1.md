# Lec 1 导论与设计思维（Introduction and Design Thinking）

> 对应Spring 2026 Class 1。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；核心阅读：[PDD第8版](https://www.mheducation.com/highered/product/Product-Design-and-Development-Ulrich.html)第1–3章。

## TL;DR

- 成功创新同时要求真实需要、可行方案与可持续价值；设计思维把观察、定义、构思、原型和测试组织成反复迭代的学习过程。
- 产品开发把市场、设计、工程与商业判断放进同一流程，团队必须先表达机会，再逐步承诺具体解法。
- 首次作业要求提交两个“解法中立”的市场机会，迫使团队把用户问题与自己偏爱的产品点子分开。

## 创新与产品开发

课程从成功创新的要素、产品开发过程和设计思维开始。设计思维不是一条只前进一次的线，而是一组可反复调用的活动：接触真实情境、重新定义问题、扩展候选解、把想法外化为原型，再用反馈修正理解。

::: definition [解法中立的机会]
机会陈述描述目标用户、使用情境、未满足需要、现有替代方案和潜在价值，但不预设产品形态、技术原理或功能清单。
:::

## 课程项目的边界

本课程优先选择有可证明市场、零件少于约10个、可在1000美元内制作原型、不依赖技术突破且能接触至少10名潜在用户的项目。这些约束不是限制创造力，而是保证一个学期内能够完成真实研究、制作和测试。

## 从机会而非点子开始

个人作业要求提交两个机会，各用2–4个词命名，并用短文说明客户需要、竞品不足、目标市场和大致规模。此时不应提出具体解法。后续机会锦标赛会让大量候选项先获得低成本评价，再把研究投入集中到少数高潜机会。

::: insight [先延迟解法承诺]
越早把机会写成某个具体产品，后续访谈越容易变成对该点子的推销或确认。先固定“谁在什么情境下为何受阻”，才能让不同学科成员在同一问题上提出真正不同的技术与体验路径。
:::
