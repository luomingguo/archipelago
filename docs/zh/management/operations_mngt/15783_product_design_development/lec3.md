# Lec 3 客户需求分析（Customer Needs Analysis）

> 对应Spring 2026 Class 3。原始链接：[课程大纲](https://studylib.net/doc/28287998/syllabuspdd-spring-2026--1-)；核心阅读：[PDD第8版](https://www.mheducation.com/highered/product/Product-Design-and-Development-Ulrich.html)第5章。

## TL;DR

- Needfinding通过观察、访谈和情境材料收集顾客之声，目标不只是记录明确要求，还要发现未被处理和难以言说的潜在需要。
- 原始陈述必须保留来源，再转写为不绑定解法、可分层组织的需要；研究者的解释不能冒充用户原话。
- Sprint 1要求使命陈述、观察式访谈、用户画像、客户旅程、需求清单和竞品分析共同形成可追溯的田野研究证据。

## 从顾客之声到客户需要

顾客之声是用户在具体情境中的语言、动作、规避方式和替代行为；客户需要则是团队对这些材料的结构化表达。两者之间必须保留追溯关系，以便后来检查某条需要究竟来自广泛模式、个别意见还是团队猜测。

::: definition [潜在需要]
潜在需要是用户未直接提出、却可从行为矛盾、临时变通、反复失败或情绪反应中推断出的目标。它仍需后续验证，不能因为“用户没有说出口”就免于证据要求。
:::

## Sprint 1的研究动作

1. 写出项目使命陈述，固定目标市场、核心收益和边界。
2. 在真实使用环境中进行观察式访谈并记录照片。
3. 建立一至两个代表关键用例的用户画像。
4. 沿客户旅程整理痛点、惊喜点、显性需要和潜在需要。
5. 分析竞品的关键优势与弱点。
6. 必要时再调查偏好和权衡；课程不强制做重要度问卷。

::: pitfall [把解决方案写进需要]
“需要一个手机App提醒我”已经锁定渠道；“在注意力转移时仍能及时获知状态变化”才保留设计空间。转写时应描述用户希望达到的结果，而不是团队准备制造的功能。
:::

::: insight [异常行为通常比偏好表态更有信息]
用户对“理想产品”的回答容易受到礼貌、记忆和想象限制；实际环境中的绕行、重复确认、自制工具和放弃动作，往往更能揭示尚未满足的需要。研究计划应主动寻找这些行为证据。
:::
