# Lec 04 行政数据系统项目重组（ADP B & C）：项目挽救与范围控制 (Case: Administrative Data Project B & C)

> MIT Sloan School of Management · 15.568 Practical Information Technology Management

## TL;DR

- 行政数据系统（ADP B & C 阶段）展示了濒临崩溃的大型 IT 项目如何通过激进的组织手术实现断臂求生。
- 新任危机领导者通过强硬收拢决策集权、砍除 70% 边缘定制功能并重构合同对齐甲乙方利益，扭转了项目颓势。
- 项目拯救的深层法则是确立分批分期上线（Phased Rollout）策略，用阶段性小胜利重新赢回组织信任。

## 危机重组：新领袖的铁血手术 / Case Context: The Turnaround of ADP (B)

在经历 ADP (A) 阶段几乎摧毁全校信心的严重危机后，校董事会解除了原项目总监和委员会负责人的职务，紧急空降了一位拥有深厚工业界实战救火经验的新任 CIO 统帅全局。

面对烂尾的千万级泥潭，新任领导者深刻认识到：**继续在原有混乱的轨道上修修补补只是慢性自杀，必须对项目的权力结构、范围定义与协作契约施加雷霆手段**。

::: definition 危机项目抢救四大急救原则 (Project Turnaround Principles)
1. **彻底冻结所有新需求 (Feature Freeze)**：坚决关闭一切新的功能诉求入口，严禁各院系再递交任何哪怕看似微小的修改申请；
2. **强行实施“二八定律”范围大砍杀 (Radical De-scoping)**：将原本庞杂的 1500 页需求规格书强行削减 70%，仅保留保障学校最基本运转（发工资、学生选课交学费、科研账务合规）的核心必须功能（Must-Have）；
3. **收拢绝对决策集权 (Centralized Command)**：彻底解散充斥着政治扯皮的二十人庞大委员会，改组为由新 CIO、CFO 与常务副校长构成的三人核心战时执行小组，拥有排他的最终生杀大权；
4. **重构商业合同激励模型**：废除有利于承包商磨洋工的时间/材料（T&M）合同，强硬重签附带严厉延期罚款与提前交付对赌奖金的**固定总价+关键里程碑绑定合同（Fixed-Price Milestone-Based）**。
:::

## 范围控制艺术与分期上线策略 / Scope Control & Phased Rollout in ADP (C)

在随后的 ADP (C) 阶段，救火团队彻底废弃了原定“全校所有系统在某一天全量一刀切切换（Big Bang Go-Live）”的自杀式部署策略。

```mermaid

    subgraph BigBang [被否决的自杀式策略：全量一次性大切换 (Big Bang)]
        BB["选课系统 + 工资系统 + 财务核算 + 捐赠系统<br/>在同一天全部强行切断旧系统上线新系统<br/>(单点故障即引发全校彻底停摆)"]
        style BB fill:#ffdddd,stroke:#ff0000
    end

    subgraph Phased [获胜的稳健救火策略：分期解耦灰度上线 (Phased Rollout)]
        direction TB
        P1["第一阶段：核心总账与工资发放 (先跑通财务底座)"]
        P2["第二阶段：试点单个学院选课系统 (小范围真实验证)"]
        P3["第三阶段：全校学籍与报销全量铺开 (风险可控收敛)"]
        P1 --> P2 --> P3
        style P3 fill:#ddffdd,stroke:#00aa00
    end
```

如上图所示，救火团队推行了严密的分期渐进交付路线：
- **步骤一：并行双轨运行（Parallel Run）**。新财务工资系统上线的前两个月，老旧大型机系统并不立即下线，而是由数据录入员在两套系统中同时录入。每个周末对两套系统的计算报表进行逐笔比对。只有当新系统连续 60 天未出现一分钱账目偏差时，才正式批准废除旧系统；
- **步骤二：设立“落后者成本自负”机制**。新 CIO 对各院系宣布：学校中央系统只提供标准通用的学分与财务接口；如果有哪个学院坚决要保留自己极其特殊的个性化选课流程，该学院必须自行掏出院系自有资金招聘外部工程师开发对接适配器，中央财政不再为此买单。这一招精妙地利用经济学激励，瞬间消解了 90% 的无理定制诉求。

## 危机重组的成果与深层反思 / Legacy of the ADP Turnaround

经过 18 个月的艰苦奋战，ADP 项目最终在压缩范围后的新预算内成功实现了安全软着陆：
- 财务与选课系统分批平稳上线，经受住了开学选课季的真实洪峰考验；
- 学校彻底甩掉了服役三十年的 COBOL 大型机硬件包袱，年度系统维护成本较旧主机降低了 40%；
- 沉淀了一支懂架构、懂业务、纪律严明的核心校内 IT 管理干部队伍。

然而，这场重组也留下了深刻的伤痕与组织政治代价：部分院系由于强势诉求被砍，对中央 IT 团队产生了长期的怨恨情绪；同时，为了赶工期，系统的许多用户交互界面（UI）较为简陋，后续数年不得不持续投入人力进行体验升级。

## 我的理解与实践洞察 / Personal Insight

::: insight 救火项目管理的最高境界是“管住贪婪，重塑预期”
ADP (B & C) 案例展示了大型系统工程管理中最稀缺的领导力品质——在悬崖边缘对业务方说“不”的勇气与智慧：
1. **“完成”永远比“完美”重要一万倍（Done is better than perfect）**：在危机时刻，业务方往往陷入非理性的全能幻想，既想要全面的高级报表，又想要极致的用户体验，还要求在下个月必须上线。卓越的项目挽救者必须冷酷无情地用冰冷的现实击碎幻想，逼迫业务方做出残酷的减法排序：“如果只能选择一个能用的系统或者一个破产的废墟，你们到底选哪个？”
2. **小步快跑是重建组织信任的唯一解药**：当一个团队连续延误两年后，无论向高管层提交多么精美的 PPT 承诺，都无法消除大家的猜忌与鄙视。唯一的突围方法就是放弃宏大叙事，把大工程切碎为一个个微小的、两周或一个月就能看见真实成果的微型里程碑。每一次按时交付并兑现承诺，都是在向组织的信任银行账户中重新存入一笔宝贵的本金。
:::
