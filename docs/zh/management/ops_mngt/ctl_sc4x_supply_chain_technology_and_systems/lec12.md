# Lec 12 软件选型与实施（Software Selection & Implementation）

> 对应 MIT CTL.SC4x · Supply Chain Technology and Systems · 第 12 讲  
> 核心参考：*SC4x Key Concept Document* (Summer 2019) & MITx MicroMasters SCM 课程大纲

## TL;DR

- 企业级软件选型遵循严格流程：需求定义、RFI/RFP 编制、供应商演示、概念验证（POC）与谈判。
- 总体拥有成本（TCO）除初始许可费外，必须充分计入二次开发、数据迁移、云资源及长期运维开销。
- 实施核心风险在于组织变革阻力与流程定制泛滥，倡导“尽量调整业务适应标准系统”而非深度二开。

::: insight 定制化诅咒（Customization Trap）
在供应链软件实施中，企业管理层最常见的失误是试图让软件 100% 复制过去的纸质或 Excel 工作习惯，要求厂商做成百上千处定制化开发。这不仅导致项目交付工期严重延宕、预算翻倍，而且在未来系统升级时会陷入巨大的维护深渊。除非某项特有流程是企业不可替代的垄断核心优势，否则应当坚定利用成熟商用软件的“最佳业务实践（Best Practice）”倒逼企业组织流程再造。
:::

## 1. 本讲的定位

前面几讲介绍了各种供应链系统（ERP、APS、TMS、WMS、MES）以及可视性能力。企业在真正选购这些系统时，需要清楚指导决策的各项因素——本讲讨论**软件选型与评估的流程**。而**选对软件只是难题的一半，真正实施起来往往更难**：实施过程可能漫长而昂贵，消耗大量额外资源。本讲的重点是：面对系统实施，应该做好哪些准备。

## 2. 架构（Architecture）的演化

要理解供应链系统现状，有必要回顾从 1970 年代开始的**架构演化历程**：

| 年代 | 架构形态 |
|---|---|
| 1970 年代 | 大型机（Mainframe） |
| 1980 年代中期 | 个人电脑（Personal Computers） |
| 1980 年代末-1990 年代初 | 客户端-服务器（Client-Server） |
| 1990 年代中期至今 | 万维网与 Web 2.0 |
| 当下及未来 | 云计算 / 后 PC 时代（Cloud / Post-PC） |

如今企业可以选择的架构格式包括：**"本地部署"（On Location / On Premise）**——企业在自己的场地/硬件、自己的防火墙内托管软件；也可以选择**云计算**。企业正日益转向云计算，这意味着他们面前有多种**部署模型**可供选择。

## 3. 云计算的三种服务模式（选型视角）

云计算日益流行，其提供的服务形态可以根据企业需求量身定制。三种主要形态：**IaaS、PaaS、SaaS**——从 IaaS 到 SaaS，**第三方管理的比重逐渐增加**。

| 服务模式 | 内容 | 企业侧责任 | 优势 |
|---|---|---|---|
| **IaaS（基础设施即服务）** | 第三方提供计算基础设施、物理或虚拟机及其他资源 | 企业自己拥有并管理软件应用 | 无需自建硬件投资；基础设施可按需弹性扩展以支持动态负载；灵活的创新服务随需可得 |
| **PaaS（平台即服务）** | 第三方提供计算平台，含操作系统、数据库、Web 服务器等 | 企业自己拥有并管理软件应用 | 更快开发应用并推向市场；几分钟内即可把新 Web 应用部署到云端；借助中间件即服务降低复杂度 |
| **SaaS（软件即服务）** | 第三方提供应用软件的访问权限，并负责安装、设置、维护和运行 | 企业按使用量付费 | 可快速注册并开始使用创新的商业应用；应用和数据可从任何联网设备访问；即便本地设备损坏，数据也不会丢失（数据在云端）；服务能根据用量动态伸缩 |

**云计算普遍存在的劣势**（不限于）：供应商中断（outage）风险、政府无限制访问的可能性、安全与隐私风险、关键数据与流程都依赖网络连接才能访问。

## 4. 软件来源（Software Selection Sources）

企业在选择软件供应商时，需要了解不同的软件来源：
- **定制化内部系统（Custom In-house）**：为某一业务量身设计；
- **ERP 扩展系统（ERP Expanded）**：在 ERP 基础上加装针对企业定制的附加功能；
- **市场最佳方案（Best of Breed Solutions）**：市面上针对具体职能的最优解决方案；
- **最佳方案平台（Best of Breed Platforms）**。

### 4.1 外包（Outsourcing）

企业还可以选择把部分系统**外包**给不同的服务提供商。以物流为例，**第三方物流提供商（3PL）**可以既运行软件，又承担相应的业务流程执行。让 3PL 运行物流业务，能省去自建软硬件的需要，3PL 甚至可能替代企业内部部分人员——这种模式在**中小企业**中最为常见。

**外包的主要理由**：降低软件和硬件的资本支出；借助合作伙伴的规模经济降低成本（3PL 往往能做得更快更好，也更灵活敏捷）；有机会以合理成本提升服务水平；企业可以专注核心业务，同时引入自身负担不起的专业能力。

**不外包的主要理由**：安全与隐私顾虑首当其冲——意味着别人能访问企业的数据；对**供应商依赖与锁定（vendor lock-in）**的担忧；企业可能因此**丧失核心职能的内部专业能力**；存在高额的**迁移成本**；以及对可用性、性能、可靠性的顾虑。企业需要权衡外包的利弊，结合自身业务目标决定是否适合外包。

## 5. 软件供应商选择流程

最终，企业必须选定供应商。通常会遵循一套组织化、正式化的流程：

1. **组建项目团队**（内部和/或外部）并明确目标；
2. **理解业务与需求**：回顾现有业务流程，为需求/功能排优先级，形成**信息征询书（RFI）**；
3. **创建候选方案与供应商的初步短名单**；
4. **深入评审入围供应商**：让供应商进行贴近实际场景的产品演示，并向现有用户核实参考案例；
5. **创建并分发最终的提案征询书（RFP）**；
6. **做出决策**：谈判合同、价格与服务水平协议（SLA），并制定实施计划。

### 5.1 十项评价标准

成本固然是决策中的首要因素之一，但还有许多其他标准需要综合评估：

| 标准 | 评估问题 |
|---|---|
| **功能性（Functionality）** | 系统功能是否契合企业的流程和需求？ |
| **易用性（Ease of Use）** | 初期学习曲线和日常使用的顺畅程度如何？ |
| **性能（Performance）** | 处理速度如何？ |
| **可扩展性（Scalability）** | 系统能否随企业成长而良好扩展？ |
| **互操作性（Interoperability）** | 与其他系统的集成程度如何？ |
| **可扩展定制性（Extendibility）** | 系统能否被轻松扩展或定制？ |
| **稳定性（Stability）** | 在漏洞和正常运行时间方面，系统的可靠程度如何？ |
| **安全性（Security）** | 系统限制访问、控制机密数据、防范网络攻击的能力如何？ |
| **支持（Support）** | 供应商在实施、支持、培训、行业前瞻等方面的服务质量如何？ |
| **供应商可持续性（Vendor Viability）** | 供应商的财务实力、是否愿意持续提供更新与增强？三年后它还会在吗？ |

由于评估标准繁多，**记分卡（Scorecard）**是一种常见方式，用来同时捕捉财务与非财务属性；评分可以采用排名、评级、打分等方式；记分卡通常做得非常细致，甚至可以按具体功能点逐项拆解；对比对象既可以是不同供应商，也可以是不同的托管平台方案。

## 6. 总体拥有成本（Total Cost of Ownership, TCO）

选型不能只看采购价，必须核算完整的总体拥有成本：

| 成本项 | 说明 |
|---|---|
| **软件许可（Software License）** | 软件系统本身的直接购买成本（假定为拥有制） |
| **维护（Maintenance）** | 保证升级和修复漏洞的持续年度成本 |
| **平台/硬件（Platform/Hardware）** | 运行新软件所需的硬件成本 |
| **培训（Training）** | 初期及后续人员培训成本 |
| **实施（Implementation）** | 让系统真正上线运行的成本，因系统和企业而异，差异很大 |
| **定制化（Customization）** | 为契合企业流程而修改系统本身的成本——供应链管理领域几乎没有软件是"开箱即用"（vanilla）的 |
| **系统集成（System Integration）** | 让该系统与其他模块对接、并修改现有系统以适配的成本 |

## 7. 实施（Implementation）

相比选型的难度和耗时，**真正的实施过程往往消耗更多的时间和资源**。四种主要实施方式：

| 方式 | 特点 |
|---|---|
| **直接切换 / 大爆炸式（Direct / Big Bang）** | 新旧系统一次性整体切换 |
| **并行运行（Parallel）** | 新旧系统同时运行一段时间，逐步验证后再切换 |
| **试点（Pilot）** | 先在小范围/单一单元试运行，验证后再全面推广 |
| **分阶段 / 滚动式（Phased / Rolling）** | 按模块或按单元分批逐步上线 |

每种方式各有利弊，具体选择需要**匹配企业自身的业务需求**。

### 7.1 实施最佳实践

1. **争取高层管理承诺**：确保能调动并使用资源、赋权项目团队；
2. **组建跨职能团队**；
3. **制定清晰、具体的范围文档**；
4. **在项目计划中纳入充分的测试**（测试怎么做都不为过）；
5. **在项目计划中纳入充分的用户培训**。

## 8. 本讲小结与学习目标回顾

- 认识到软件供应商的选择，是**架构**与**来源**两方面相互交织的决策；
- 理解本地部署与云端系统之间的权衡；
- 了解内部定制、市场最佳方案、ERP 扩展、外包这几类软件系统形式之间的差异；
- 复习选型流程，认识到评估涉及多项属性，且总体拥有成本相当复杂；
- 理解系统实施所面临的挑战，以及各类实施方式；
- 复习实施的最佳实践。
