# Lec 8 供应链信息系统——ERP（Supply Chain Systems - ERP）

> 对应 MIT CTL.SC4x · Supply Chain Technology and Systems · 第 8 讲  
> 核心参考：*SC4x Key Concept Document* (Summer 2019) & MITx MicroMasters SCM 课程大纲

## TL;DR

- ERP 是企业运营的核心中枢，打破部门信息壁垒，实现财务、供应链与生产数据的单一真理源。
- 主数据管理（物料主数据、BOM、工艺路线）是 ERP 稳定运行的基石，直接决定 MRP 准确性。
- 物料需求计划（MRP）逻辑将独立需求通过 BOM 逐级展开为相关需求，生成采购与生产指令。

::: insight “垃圾进，垃圾出”与主数据治理
许多企业花费千万资金实施 SAP 或 Oracle ERP 却未能提升周转率，根源往往不在软件本身，而在于物料主数据（Master Data）的极其混乱——例如同一规格轴承在不同车间有五个不同编码、BOM 层级配比错误或提前期（Lead Time）未随季节更新。ERP 本质上是一个确定性的确定性推理机；主数据治理如果不到位，ERP 只会以更高效率加速制造错误。
:::

## 1. 本讲的定位

前七讲讲完了数据、数据库、SQL 和机器学习这些"通用技术工具"；从本讲开始，进入供应链领域**特有的企业信息系统**。供应链本质上由三种流构成：**信息流、物流（实物）、资金流**。IT 系统的职责就是支撑**信息流**的运转。

以超市为例：系统要处理供应商库存、设施管理与薪资、销售、过期与报废库存等多种类型的数据；一家门店每周的交易信息量就可能达到**百万级别**——这仅仅是单店的数据量。

在企业层面，公司需要系统来管理和组织这些信息。虽然教科书里供应链常被描绘成整齐的线性系统，但现实要复杂得多：物料/信息在链条上上下游来回流动，要经过许多合作伙伴才能到达最终目的地。供应链需要 IT 系统的根本原因：不同职能团队即便分处不同部门，也需要频繁共享信息；同时，多家企业之间的互动也需要系统来传递信息、帮助**去孤岛化（de-silo）**。跨职能的协调正是供应链管理的本质所在，而这可以借助 **ERP（Enterprise Resource Planning，企业资源计划）**这类系统来实现。

## 2. 供应链 IT 系统的分类

供应链需要 IT 系统的原因：规模大、复杂、涉及众多参与方；各参与方经常相互交织、相互影响；决策依赖于共同的数据以及与企业内其他职能的互动；此外 IT 系统还支撑供应链中的 **B2B（企业对企业）、B2C（企业对消费者）、M2M（机器对机器）** 等多种交互形式。

供应链 IT 系统大致分为三大类：

| 类别 | 定位 |
|---|---|
| **ERP（企业资源计划）** | 作为企业总账（general ledger）与所有企业活动的中央数据库 |
| **供应链计划系统（Supply Chain Planning Systems）** | 主要用于生产计划与排程、需求计划、产品生命周期管理（详见 Lec9） |
| **供应链执行系统（Supply Chain Execution）** | 运输与仓库管理系统、制造系统（详见 Lec9 / Lec10） |

本讲先聚焦第一类：**ERP**。

## 3. 为什么企业要用 ERP

多数企业都拥有 ERP 系统，原因在于：企业内销售、库存、生产、财务、分销、人力资源等诸多职能，各自拥有**孤立的数据库**。有了集中式 ERP，这些数据库之间的信息交换会容易得多。

**ERP 的好处**：帮助企业组织流程与数据结构、把信息整合进统一的存储库、让数据可被众多用户使用、消除冗余系统与数据、减少非增值任务、标准化流程设计，同时提升灵活性。

**ERP 的显著缺点**：实施耗时长、维护成本高；数据错误会在系统间连锁传导；可能削弱企业的竞争优势；企业会对单一供应商产生**依赖**；掌握该系统技术知识的人员**短缺**；系统一旦宕机，**影响面很大**。

## 4. ERP 的核心功能模块

多数 ERP 系统共享同一组核心功能，它们把企业内的基础业务流程**串联并自动化**：

| 模块 | 面向对象 | 核心职能 |
|---|---|---|
| **客户管理（Customer Management）** | 消费者 | 订单录入、订单承诺（order promising）、开放订单状态查询；支持市场部设定定价方案、促销和折扣；提供实时盈利能力分析；支持订单配置、客户交付计划、客户退货、税务管理、货币转换等 |
| **制造（Manufacturing）** | 生产 | 包括 MRP 处理、生产订单下达、在制品（WIP）管理、成本报告、车间控制等；提供需求与供应管理的实时联动，支持实时**可承诺量（ATP）**与**可生产量（CTP）**；作为高级计划与排程优化模块（"外挂"模块）的主要接口 |
| **采购（Procurement）** | 供应商 | 把采购与供应商管理整合起来；支持采购订单处理、交付排程、开放订单跟踪、收货、检验、供应商绩效报告；创建询价单（RFQ）；管理谈判与定价能力 |
| **物流（Logistics）** | 企业内外部供应链 | 支撑企业内部供应链运转；提供与远端贸易伙伴（3PL、承运商等）的连接；处理分销渠道配置、仓库活动管理、渠道补货、计划、分销订单管理等；作为仓库管理系统与运输管理系统（WMS 和 TMS，"外挂"模块）的主要接口 |
| **产品数据（Product Data）** | 所有物料 | 描述生产商和/或分销商的产品；包含成本、来源、工程细节、尺寸、重量、包装等专有数据；与库存、制造、产品生命周期管理对接；有时也会被纳入合作伙伴协作，用来压缩新产品上市时间 |
| **财务（Finance）** | CFO | 对库存变动、应收账款、应付账款、税务、外币转换及其他所有分录产生的交易，提供实时报告；支持详细的报表与预算能力 |
| **资产管理（Asset Management）** | 关键资产 | 控制企业的固定资产；建立并维护设备档案、诊断与预防性维护活动、折旧活动 |
| **人力资源（Human Resources）** | 员工 | 管理企业人力资本的方方面面；监控考勤、薪酬、补偿、报销、招聘等交易活动；支持员工档案、技能发展、职业规划、绩效评估与留任 |

## 5. ERP 数据的三种类型

| 类型 | 定义 |
|---|---|
| **组织数据（Organization Data）** | 表示并记录企业自身的组织结构 |
| **主数据（Master Data）** | 表示与流程相关联的实体（如客户、供应商），是**使用最频繁**的数据类型；但由于不同流程对物料的使用方式不同、各流程对数据的具体需求也不同，这使得主数据的需求变得复杂——物料类型可能处于不同状态，并根据企业需要被以不同方式分组 |
| **交易数据（Transaction Data）** | 反映流程步骤执行后的结果；同时包含组织数据、主数据和情景数据；交易单据包括采购订单、发票等 |

## 6. ERP 之间的通信

- **B2B（Business-to-Business）**：制造商、批发商、零售商之间的商业交易，供应链上每家企业都是链条中的一环；
- **B2C（Business-to-Consumer）**：企业与终端消费者之间的销售交易；**B2B 交易量远大于 B2C**；
- **加速并校验 B2B / B2C 交易**：B2B 主要通过 **EDI（Electronic Data Interchange，电子数据交换）**实现；B2C 主要通过网站和邮件实现；
- **EDI**："以严格格式化的报文，在计算机之间交换代表非货币票据类文件的信息"——整个过程**没有人工介入**；
- ERP 系统之间可以通过 EDI **近实时**地"沟通"信息共享。

## 7. ERP 对供应链管理的价值

ERP 对 SCM（供应链管理）有三大重要价值：**削弱牛鞭效应、赋能广泛的数据分析、延伸企业边界**。

### 7.1 削弱牛鞭效应（Bullwhip Effect）

ERP 的一大核心价值在于**削弱或预防牛鞭效应**——牛鞭效应是指信息失真导致供应链上游订单波动被逐级放大的现象（发生在依赖预测驱动的供应链中）。它由若干行为性原因驱动，如对积压订单的过度反应、透明度不足；也存在诸多操作性误差，如预测误差、提前期波动、促销活动等。

ERP 可以通过以下方式削弱牛鞭效应的影响：把可视性向下游延伸至客户需求、向上游延伸至各参与方，从而促成协作与信息共享；同时便于**销售点（POS）数据捕获**，并通过更小、更频繁的订单，帮助减小批量规模和需求波动。

### 7.2 赋能数据分析

ERP 系统在赋能数据分析方面扮演关键角色。它们本质上是**回顾性（retrospective）**的，充当企业的总账，为 CFO 提供财务快照。同时也支撑其他形式的**商业智能（Business Intelligence, BI）**分析——把原始数据转化为有意义的信息，以改善业务决策，可以是**描述性、预测性、规范性（prescriptive）**分析。

### 7.3 延伸企业边界

ERP 系统主要用于企业内部流程管理，连接各部门、提供数据访问权限；同时它也发挥"延伸"功能，更好地与合作伙伴对接。ERP 在连接**端到端供应链**方面提供价值：促成供应链参与方之间更好的连接、建立共同理解、降低协调与监督成本、更快响应市场反馈。
