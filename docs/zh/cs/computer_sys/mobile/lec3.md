# Lec 3 GPS 与实用室内定位（GPS & Practical Indoor Localization）

> MIT 6.1820 / MAS.453 · Mobile and Sensor Computing  
> 阅读材料：RADAR [INFOCOM'00]，Cricket [MobiCom'00]

## TL;DR

- GPS 利用 4 颗卫星伪随机码互相关测距，联立求解三维空间坐标与接收机时钟偏差。
- A-GPS 借助蜂窝与 Wi-Fi 网络带外预分发星历，将首次定位时间（TTFF）从十余分钟压缩至秒级。
- RADAR 开创性地将既有商用 Wi-Fi 信号强度指纹空间化，无需专用硬件达成米级室内定位。
- Cricket 结合被动监听器架构与射频/超声波异质到达时差，在严格保护隐私前提下实现厘米级测距。

## 1. GPS 工作原理与工程解算

全球定位系统（GPS）是现代室外导航的基础，其底层建立在光速脉冲的单向飞行时间（ToF）测量之上。

### 1.1 伪随机噪声码与互相关测距

每颗 GPS 卫星都持续广播具有极高自相关特性的**伪随机噪声码（PRN, Pseudo-Random Noise Code）**。

::: definition 互相关时延估计（Cross-Correlation Time Delay Estimation）
接收机在本地生成与各卫星 PRN 严格一致的基准码序列 $s(t)$，与接收到的微弱天线射频信号 $r(t)$ 执行连续互相关运算：

$$R(\tau) = \int_{-\infty}^{\infty} r(t) \cdot s(t - \tau)\, dt$$

当且仅当本地时移 $\tau$ 与无线电波从卫星传播至地面的实际时延 $\Delta t$ 完美重合时，互相关函数产生一个剧烈的能量尖峰（Correlation Peak）。尖峰横坐标即对应飞行时间：

$$d = \Delta t \times c$$
:::

由于不同卫星分配了正交的 Gold 码，接收机仅需一套射频前端即可在码分多址（CDMA）架构下并行解调所有可视卫星。

### 1.2 四星解算：消除接收机低成本时钟误差

卫星端搭载昂贵的原子钟（铯钟/铷钟，纳秒级误差），而地面手机仅有廉价石英晶振，存在无法忽视的时钟漂移 $\Delta t_{clock}$。

因此，实际测得的并非真实几何距离，而是**伪距（Pseudorange）** $\rho_i$：

$$\rho_i = \sqrt{(x_i - x)^2 + (y_i - y)^2 + (z_i - z)^2} + c \cdot \Delta t_{clock}$$

::: theorem 最小观测卫星数定理
空间中待求解的未知量共有 4 个：接收机三维空间坐标 $(x, y, z)$ 以及接收机时钟偏差 $\Delta t_{clock}$。因此，系统必须至少同时锁定 4 颗非共面卫星，联立非线性方程组方可唯一解算真实位置并同步本地时钟。
:::

### 1.3 辅助 GPS（A-GPS）的技术跨越

- **传统 GPS 瓶颈**：卫星轨道参数与时钟修正信息（星历 Ephemeris）的数据传输速率仅为 **50 bps**。冷启动时完整下载全部星历需耗时约 **12.5 分钟**，首次定位时间（TTFF, Time to First Fix）极慢。
- **A-GPS 破局**：移动终端通过蜂窝网络基站或 Wi-Fi 连接，直接经由高速互联网从辅助服务器拉取当前可视卫星星历与粗略基站坐标，将 TTFF 骤降至 1–2 秒内。

## 2. 论文一：RADAR [INFOCOM'00] — 经验指纹匹配开山之作

微策略实验室（Microsoft Research）发表的 RADAR 系统是学术界首篇将现有商用无线局域网（802.11b Wi-Fi）用于室内定位的经典工作。

### 2.1 核心思想：空间无线电指纹（Radio Map）

RADAR 放弃了在复杂多径室内建立确定性衰减物理模型的尝试，转而构建基于统计经验的无线电地图：

```text
离线建图阶段 (Offline):
  在建筑物网格点 (x, y) 采集多方向 Wi-Fi RSSI 向量 → 构建数据库 [(x_j, y_j): ss_j]

在线定位阶段 (Online):
  移动端实时采集 RSSI 向量 ss' → 计算与数据库条目的欧氏距离 → k-NN 加权坐标输出
```

在线测量向量 $\mathbf{ss}' = [s_1', s_2', \dots, s_k']$ 与预存记录 $\mathbf{ss}_j$ 的信号距离为：

$$d_\text{ss}(\mathbf{ss}', \mathbf{ss}_j) = \sqrt{\sum_{i=1}^{k} (s_i' - s_{i,j})^2}$$

系统选出信号距离最小的前 $k$ 个候选物理坐标，通过加权平均解算出最终估计位置。

### 2.2 评估与局限

::: example RADAR 评估合理性分析
RADAR 论文在走廊与办公区选取了 70 个测试点。当使用留一法交叉验证（Leave-One-Out）时，系统宣称中位误差在 2–3 米。
然而，其关键局限在于：
1. **方向性阻挡**：人体对 2.4 GHz 信号有 3–5 dB 的衰减，用户面朝不同方向会导致指纹显著变化；
2. **环境动态性**：开门、关门及人员走动破坏静态多径，造成指纹漂移；
3. **采集成本**：整栋大楼的网格标定需要密集人工测绘，维护成本随空间面积线性膨胀。
:::

## 3. 论文二：Cricket [MobiCom'00] — 保护隐私的厘米级声学测距

MIT CSAIL 团队设计的 Cricket 室内定位系统，旨在彻底颠覆“网络端追踪用户”的旧范式，确立“空间基础设施支持终端定位”的新原则。

### 3.1 架构设计：被动监听器 + 主动天花板信标

::: definition 被动监听器架构（Passive Listener Architecture）
- **天花板信标（Active Beacons）**：周期性主动广播自身位置标识与同步信号，完全不接收任何数据。
- **用户终端（Passive Listeners）**：仅被动接收信号并在本地计算自身坐标，不向空间发射任何无线电或声波。
- **根本优势**：彻底杜绝位置信息被中心服务器窃取，支持无限量移动用户在不抢占无线信道的前提下自主定位。
:::

### 3.2 测距机制：RF 与超声波到达时差（TDoA）

信标在同一时刻并发发射两路异质物理信号：
1. **射频数据包（RF Packet）**：以光速 $c \approx 3 \times 10^8\text{ m/s}$ 传播，附带信标位置元数据。
2. **超声波脉冲（Ultrasound Pulse）**：以声速 $v_{sound} \approx 345\text{ m/s}$ 传播。

监听器收到 RF 数据包瞬间开启高精度硬件定时器，直至麦克风检测到超声脉冲边沿，记录两者传播时间差 $\Delta t_\text{RF-US}$：

$$d = \Delta t_\text{RF-US} \times v_{sound} \quad (\text{因 } c \gg v_{sound})$$

::: theorem 为何采用超声波而非纯射频 ToF？
- **声速物理尺度**：$v_{sound} \approx 345\text{ m/s}$，空间传播 $10\text{ cm}$ 对应耗时约 $290\ \mu\text{s}$。低功耗 8 位单片机即可通过标准 GPIO 中断实现亚毫米级的计时分辨率。
- **光速物理尺度**：电磁波传播 $10\text{ cm}$ 仅耗时约 $0.33\text{ ns}$，接收端必须配备采样率超过 3 GSps 的高频模数转换器与飞秒级锁相环，硬件成本与功耗高出数个数量级。
:::

### 3.3 多信标并发碰撞抑制策略

当多个信标未同步发射时，空间可能出现致命的“交叉配对错误”（Cross-pairing Error）：信标 A 发射的 RF 意外匹配了信标 B 发射的超声波。

Cricket 提出了成套解决机制：
- **分布式随机退避**：信标广播周期引入伪随机抖动，避免长期相干碰撞。
- **长射频包锁定原则**：配置射频数据包的空中传输时长大于最大房间直径下的超声最长飞行时间 $\tau_{max} = 2 d_{max} / v_{sound}$。
- **相关性检验与鲁棒统计**：监听器在滑窗内采用最小均值（MinMean）或最小众数（MinMode）统计学滤波，直接剔除因多径反射声波引起的非视距野值。

## 4. RADAR 与 Cricket 的系统对比

| 评估维度 | RADAR (INFOCOM'00) | Cricket (MobiCom'00) |
|:---|:---|:---|
| **核心物理机制** | Wi-Fi 接收信号强度（RSSI）指纹欧式匹配 | 射频（RF）与超声波（US）到达时间差（ToA/TDoA）|
| **典型定位精度** | 2 ~ 3 米（房间级） | 1 ~ 3 厘米（高精度坐标级） |
| **专用硬件依赖** | 零（完全复用商用 802.11 AP 与网卡） | 需在天花板与终端部署超声收发压电晶体 |
| **位置隐私保护** | 差（网络端 AP 可直接记录终端信号强度） | 极佳（被动接收，信标对终端位置完全无知） |
| **并发容量上限** | 受 Wi-Fi 关联容量限制 | 理论无限（纯下行单向广播） |
| **主要工程痛点** | 人体遮挡与环境重构导致指纹快速失效 | 超声波无法穿透墙体，视距受遮挡时精度下降 |

## 5. 架构对比与隐私设计权衡

::: insight
RADAR 与 Cricket 分别代表了移动计算系统工程两条截然不同的演化路线：
1. **寄生式复用 vs 纯粹式架构**：RADAR 展现了极高的商业智慧，它不追求物理上的极致纯净，而是“寄生”在既有的企业级 Wi-Fi 设施上。哪怕信号充满多径、精度仅停留在米级，但其边际硬件成本为零的特性让它在商用手机定位中大获成功。
2. **位置支持（Location Support）vs 位置追踪（Location Tracking）**：Cricket 在二十余年前就深刻揭示了定位系统的伦理困境——定位技术究竟应该赋予用户“认知自身所处空间”的能力，还是沦为中心服务器“监视空间中每个个体”的探针？Cricket 的被动监听设计在架构上杜绝了集中式监视的可能性，这种以物理单向信道作为不可篡改隐私边界的系统哲学，在当今去中心化追踪与普适计算中依然极具启示意义。
:::
