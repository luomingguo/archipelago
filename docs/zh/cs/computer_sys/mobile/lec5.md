# Lec 5 网络连接技术：BLE 与低功耗广域网（Network Connectivity）

> MIT 6.1820 / MAS.453 · Mobile and Sensor Computing  
> 阅读材料：AirTags 逆向分析与 BLE 安全性报告

## TL;DR

- 物联网连接面临带宽、通信距离与功耗之间的三难困境，不存在通用的最优网络协议。
- BLE 依靠纳秒级广播与毫秒级连接间隔将占空比压缩至 0.1%，实现纽扣电池数年续航。
- LoRaWAN 依托线性调频扩频（CSS）与高扩频因子，在极低速率下实现十公里级广域覆盖。
- 智能手机普及使 BLE 成为事实上的身体与房间级网关，驱动去中心化众包网络生态。

## 1. 物联网连接设计空间与系统拓扑

物联网的发展本质上是由微型机电传感（MEMS）、超低功耗嵌入式计算与无线通信协议的汇聚所驱动的。然而，无线网络并非通用即插即用的单一管道。

### 1.1 带宽、距离与功耗的“三角困境”

在物理层，无线通信的有效连接受制于不可兼得的三维权衡空间：

![物联网网络技术设计空间三维权衡图（带宽 vs 覆盖范围 vs 功耗）](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260501220102104.png)

::: definition 物联网连接的三角困境（Trilemma of IoT Connectivity）
任何无线通信系统都无法同时最大化通信距离、吞吐带宽并最小化能量消耗：
- **Wi-Fi / 5G**：带宽极高（Gbps 级）、覆盖中远，但功耗高达数百毫瓦至数瓦，无法由微型纽扣电池长期驱动。
- **LoRaWAN / NB-IoT**：覆盖达十余公里且休眠功耗低，但信道容量被压缩至数百 bps，无法承载多媒体与高频流。
- **BLE / Zigbee**：功耗与带宽平衡极佳，但有效作用距离被锁死在人体与房间尺度（10–30 米）。
:::

![物联网连接技术全景谱系与标准生态](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260501205425781.png)

### 1.2 三种主流系统拓扑架构

面对异构的物理约束，系统工程师通常在三种系统拓扑中进行权衡：

![直连、网关中继与边缘计算三种系统连接拓扑](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260501215306555.png)

1. **终端直连云端（Direct to Cloud）**：通过 NB-IoT 或 4G Cat-1 直接入网，无需现场部署任何中继设施，但硬件射频模块成本昂贵且电池难以长期维持。
2. **星型网关中继（Gateway Relaying）**：微型终端使用极轻量的 BLE 或 Zigbee 与中央网关（如智能手机、家庭路由器）通信，由网关承担协议转换与长途骨干回传。
3. **边缘就地闭环（Edge Computing & Mesh）**：在网关或本地边缘服务器执行信号过滤与局部控制，大幅削减流向公网的数据量与网络传输能耗。

## 2. 蓝牙低功耗（BLE, Bluetooth Low Energy）

蓝牙低功耗（BLE，前身为诺基亚 Wibree）并非经典蓝牙（Classic Bluetooth）的简单升级，而是一套为了极端省电而彻底重构的独立协议栈。

### 2.1 频段划分与信道抗干扰

BLE 运行在 2.4 GHz ISM 免许可频段，划分为 40 个物理信道（信道间隔 2 MHz）：
- **3 个专用广播信道（Advertising Channels 37, 38, 39）**：中心频点特意避开了 Wi-Fi 常见信道 1、6、11 的主要能量峰值，确保广播包能在严重的 Wi-Fi 干扰中高概率穿透。
- **37 个数据传输信道（Data Channels 0–36）**：双方建立连接后，基于自适应跳频（AFH, Adaptive Frequency Hopping）伪随机跳变，规避拥堵信道。

### 2.2 广播模式与连接模式

| 操作模式 | 通信方向 | 状态与拓扑 | 典型应用 |
|:---|:---|:---|:---|
| **广播模式（Advertising）** | 单向无连接 | 外设在 37/38/39 信道单向发包，观察者被动监听 | 苹果 AirTags、商用室内 iBeacon、传感器标量广播 |
| **连接模式（Connected）** | 双向点对点 | 主机（Master）与从机（Slave）锁定同步时序跳频通信 | 智能手表同步、无线心率带、助听器音频流 |

### 2.3 极低占空比工作机制（Duty Cycling）

BLE 实现纽扣电池长期运转的核心秘诀在于**将活动时间压缩到极限**。

建立连接后，从机无需保持射频常开，而是与主机约定严格的**连接间隔（Connection Interval, $T_{CI}$）**，典型取值 $7.5\text{ ms} \sim 4.0\text{ s}$。

在每个连接间隔的锚点（Anchor Point），从机唤醒接收机监听主机的 Poll 包，快速交换数个字节后立即切入微安级深度休眠：

$$\text{Duty Cycle} = \frac{T_\text{active}}{T_{CI}}$$

::: example AirTag 电池寿命推导与分析
已知某追踪标签硬件参数：
- CR2032 锂锰纽扣电池标称容量：$Q = 220\text{ mAh}$
- 射频芯片发射/接收时电流：$I_{tx} = 15\text{ mA}$
- 深度休眠漏电电流：$I_{sleep} = 1\ \mu\text{A} = 0.001\text{ mA}$
- 广播间隔设为 $T_{adv} = 1.0\text{ s}$，单次广播突发脉冲耗时 $T_{active} = 1.0\text{ ms}$

系统平均工作电流：

$$I_{avg} = I_{tx} \cdot \left(\frac{T_{active}}{T_{adv}}\right) + I_{sleep} \cdot \left(1 - \frac{T_{active}}{T_{adv}}\right)$$

$$I_{avg} = 15 \times 0.001 + 0.001 \times 0.999 \approx 0.015 + 0.001 = 0.016\text{ mA}$$

理论续航寿命：

$$t = \frac{Q}{I_{avg}} = \frac{220\text{ mAh}}{0.016\text{ mA}} = 13750\text{ 小时} \approx 1.57\text{ 年}$$

::: theorem 占空比压缩的幂级降耗效益
仅需将占空比从 100% 压缩至 0.1%，系统平均功耗便能暴降近千倍。这使得能量受限节点无需配备大体积锂电池，仅凭薄型纽扣电池即可稳定跨越数个年头。
:::

## 3. LoRaWAN：长距离低功耗广域网

当通信场景从室内走入数十平方公里的开阔农田、森林或大型矿区时，BLE 几十米的覆盖范围彻底失效。**LoRaWAN** 填补了这一空白。

::: definition 线性调频扩频（Chirp Spread Spectrum, CSS）
LoRa 在物理层采用线性调频扩频技术：载波频率在给定时隙内从低频向高频线性滑动（Chirp）。扩频技术具备极高的抗多径衰落、多普勒频移以及带内容限能力，使得接收机即使在信号功率低于环境热噪声底噪 20 dB 时仍能无差错解码。
:::

### 3.1 扩频因子（Spreading Factor, SF）的动态权衡

LoRa 定义了从 SF7 到 SF12 六个正交扩频因子。每个符号所包含的 Chirp 样本数为 $2^{SF}$：

$$\text{数据速率 } R_b = SF \cdot \frac{BW}{2^{SF}}$$

| 扩频因子 | 传输速率 | 解调信噪比门限 | 典型通信距离 | 适用场景 |
|:---|:---|:---|:---|:---|
| **SF7** | ~5.4 kbps | -7.5 dB | 2 ~ 3 km | 距离基站较近、需较高刷新率 |
| **SF10** | ~980 bps | -15 dB | 5 ~ 8 km | 郊区建筑密集阻挡 |
| **SF12** | ~250 bps | -20 dB | 10 ~ 15 km | 极限深远距离、边缘弱信号保底 |

在 LoRaWAN 架构中，网关自适应速率（ADR）算法动态评估节点链路信噪比，自动分配最优 SF，防止近处节点盲目使用 SF12 霸占宝贵的空中频谱资源。

## 4. 苹果 AirTag 逆向解析：去中心化定位与隐私博弈

苹果的 AirTag 将 BLE 广播与全球数十亿活跃 iPhone 结合，创造了人类历史上规模最大的去中心化众包定位网络（Find My Network）。

```text
  AirTag (单向广播 Rotating Public Key)
      │
      ▼ (BLE 广播, ~10m)
  路人 iPhone (作为匿名网关发现广播)
      │
      ├─> 读取本地 GPS 坐标 (x, y)
      ├─> 使用 AirTag 公钥对坐标进行非对称加密 E_pub(x, y)
      ▼ (蜂窝 / Wi-Fi 上传)
  Apple Find My 云端服务器 (仅作为密文数据库，无私钥，无法解密坐标)
      │
      ▼ (主人设备发起查询)
  失主 iPhone (持有配对私钥，拉取密文在本地解密得到位置)
```

### 4.1 隐私安全防线与漏洞交锋

1. **公钥轮换机制（Rotating Keys）**：为防止商场商户通过固定的 BLE MAC 地址追踪用户行踪，AirTag 每隔约 15 分钟重置一次发射地址与临时公钥。
2. **端到端加密零知识证明**：苹果服务器作为存储中心，仅存放大规模匿名加密块，苹果官方无法反查任何用户的真实移动轨迹。
3. **恶意追踪的反制机制（Anti-Stalking）**：当非本人的 AirTag 持续跟随某台 iPhone 超过一定阈值，受害人手机将弹窗警报并触发 AirTag 内置压电扬声器蜂鸣警示。

::: pitfall 安全与便利的双刃剑
防跟踪警报的判定阈值面临经典的“漏报与虚警”困境：若阈值设为数小时，恶意跟踪者已有充裕时间窥探受害人家庭住址；若阈值缩短至数十分钟，地铁或公交同行乘客的 AirTag 将频繁触发误报，严重损害用户体验。
:::

## 5. 连接协议演化与平台生态启示

::: insight
为什么在物联网连接领域，技术最精妙、效率最高的协议往往未能普及，反而是某些看似折中的协议大获全胜？
1. **网络效应绑定于终端硬件生态**：BLE 的爆发并非因其射频性能优于 Zigbee 或 802.15.4，而是因为智能手机（iPhone 与 Android）从 2011 年起无条件全面标配 BLE 芯片。智能手机成为了现成的随身万能网关，彻底免去了用户为物联网设备额外购买独立网关的沉重硬件门槛。
2. **协议竞争的本质是经济学博弈**：蜂窝网络运营商向往高 ARPU 值的 SIM 卡包月套餐，但这与数美元造价、数年不换电池的水表传感器格格不入。LoRaWAN 与 BLE 的繁荣正是因为它们运行在免授权频谱（Unlicensed Spectrum），让系统搭建者彻底甩开了运营商的数据税，构建起完全自主可控的微型局部网络。
:::
