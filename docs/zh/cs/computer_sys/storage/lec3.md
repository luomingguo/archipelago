# Lec 3 磁盘驱动操作

## TL;DR

- **机械构造与延迟分解**：机械磁盘（HDD）依赖物理马达旋转与磁臂寻道，单次 I/O 延迟由寻道时间（加速、匀速、减速、稳定）、旋转延迟与数据传输时间共同构成，导致随机 I/O 相比顺序 I/O 存在两到三个数量级的性能鸿沟。
- **几何细节与不成文契约**：磁道偏移（Track Skew）防止跨磁道寻道丢失旋转周期，多区域记录（ZBR）使外圈获得更高扇区密度；上层系统普遍依赖“邻近块访问更快、大块顺序读写最快”的不成文契约。
- **调度算法进化脉络**：从忽略旋转仅看磁道的 SSTF 与防饥饿的 SCAN/C-SCAN，演进到综合权衡寻道与实时旋转的最短定位时间优先（SPTF），并最终在具备微观几何感知的磁盘控制器硬件内部实现高效闭环。

## 本讲定位

前面两讲讲的 SSD 是纯电子的随机存取设备，读写任意位置代价几乎一致。第三讲回到 HDD。机械磁盘有真实的物理运动部件，访问代价强烈依赖数据的物理空间位置，这一点与固态硬盘截然不同，也正是后面文件系统布局、磁盘阵列等所有上层设计要应对的核心约束。理解机械磁盘如何工作，是理解为什么文件系统要那样精巧布局的前提。

## 磁盘接口

现代磁盘对外的接口很简洁：整个磁盘是一个扇区（*sector*，即 512 字节或 4KB 的高级格式化块）数组，编号从 0 到 $n-1$，这就是设备的逻辑块地址空间（LBA）。可以做多扇区操作，很多文件系统一次读写 4KB 或更多，但厂商唯一保证原子的只有单个物理扇区写，要么完整完成、要么完全不完成；若此时突然断电，一个较大的写可能只完成一部分，这叫撕裂写（*torn write*）。

接口之外还有一些客户端普遍依赖、却没写进规范的假设，Schlosser 和 Ganger 称之为磁盘的不成文契约（*unwritten contract*）：访问地址空间里彼此靠近的两个块，通常比访问相距很远的两个块快；按连续大块顺序读写，通常是最快的访问方式，远快于随机访问。这条契约是上层所有“尽量顺序写入”设计准则的物理根源。

## 磁盘的物理结构

让我们从理解现代磁盘的核心组成部分开始。

首先是**盘片（platter）**，它是一个圆形的硬质表面，数据通过在其上引入磁性变化来实现持久存储。一块磁盘可能包含一个或多个盘片；每个盘片有两个面，每个面称为一个**表面（surface）**。这些盘片通常由铝合金或玻璃制成，然后覆盖一层薄薄的磁性介质，使得断电后驱动器仍然能够持久保存比特数据。

所有盘片都围绕着**主轴（spindle）**固定在一起，主轴连接到一个电机，在通电时以恒定的角速度旋转盘片。旋转速度通常以每分钟转数（RPM）衡量，现代磁盘的典型转速在 7200 RPM 到 15000 RPM 之间。我们通常更关心单次旋转所需的时间，例如一个 10000 RPM 的磁盘，其单次旋转大约需要 6 毫秒（6 ms）。

数据被编码在每个表面的同心圆上，这些同心圆由许多**扇区（sectors）**组成；其中每一个同心圆称为一个**磁道（track）**。单个表面上包含成千上万条磁道，这些磁道紧密排列。

为了在表面上进行读写，需要一种机制来感知（读取）或改变（写入）磁盘上的磁性模式。这个过程由悬浮在气流之上的**磁头（disk head）**完成；每个表面都有一个对应的磁头。所有磁头安装在一个统一的**磁臂（disk arm）**上联动，磁臂可以在表面上径向移动，从而将磁头定位到目标磁道。

![机械磁盘磁道与单扇区定位模型图](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260327100211463.png)

让我们通过逐步构建模型来理解磁盘是如何工作的，从单个磁道开始。假设我们有一个只有一条磁道的简单磁盘。这条磁道上只有 12 个扇区，编号是 0 到 11。盘片围绕主轴以逆时针方向匀速旋转。

假设现在收到一个读取扇区 0 的请求。磁头当前位于扇区 6 上方。磁盘只需要等待目标扇区旋转到磁头下方。这种等待在现代磁盘中非常普遍，是 I/O 服务时间的重要组成部分，称为**旋转延迟（rotational delay）**。如果完整一圈旋转所需时间为 $R$，那么从扇区 6 开始等待扇区 0 转到磁头下方，大约需要 $R/2$ 的时间。最坏情况下（请求扇区 5），则几乎需要等待完整的一整圈旋转。

现代磁盘拥有数百万条磁道。现在我们来看一个具有三条磁道的磁盘模型：内侧磁道（扇区 24 到 35）、中间磁道（扇区 12 到 23）、外侧磁道（扇区 0 到 11）。

为了读取较远的扇区（如扇区 11），磁盘首先需要将磁臂从内侧移动到最外侧磁道，这个过程称为**寻道（seek）**。寻道与旋转一样，是机械磁盘中最昂贵的操作。

寻道过程包含四个物理阶段：
1. **加速阶段**：音圈马达驱动磁臂开始移动并加速；
2. **匀速阶段**：磁臂以全速巡航滑移；
3. **减速阶段**：磁臂反向施力减速；
4. **稳定阶段（settling）**：精确微调磁头，使其精确对准目标磁道中心线。稳定时间通常相当可观（0.5 到 2 毫秒），因为磁道极窄，稍微偏离就会导致读写串扰损坏临近磁道。

![三磁道磁盘寻道与旋转延迟分解过程图](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260327100433452.png)

完成寻道后，磁头已经位于正确的磁道上。在寻道移动过程中，盘片仍在旋转（例如转过了 3 个扇区）。因此磁头到达外圈时扇区 9 刚转过，只需再经历一段极短的旋转延迟，扇区 11 即到达磁头下方。此时进入 I/O 的最后一个阶段——**传输（transfer）**阶段，数据通过电磁感应高速读入或写入控制器缓存。

### 关键几何特性与控制器缓存

- **磁道偏移（Track Skew）**：许多硬盘会在相邻磁道之间人为错开扇区物理编号。之所以要对扇区进行这种“错位”排列，是因为当磁头从一个磁道切换到相邻磁道寻道时需要时间。如果没有偏移，磁头刚就位，目标扇区可能刚刚滑过，导致系统平白多等几乎完整一圈旋转延迟。
- **多区域记录（Zone Bit Recording, ZBR）**：由于外圈周长显著大于内圈，外圈磁道能够容纳更多物理扇区。现代硬盘将盘面划分为数十个区域（Zones），每个区域内部磁道扇区数相同，越靠外圈数据传输率（MB/s）越高。
- **驱动器内部缓存（Track Buffer）**：控制器板载通常配备 64MB 到 512MB 的 DRAM 缓存：
  - **预读（Read-ahead）**：读取一个扇区时，驱动器顺便将整个磁道的后续扇区一次性读入缓存；
  - **写回（Write-back） vs. 直写（Write-through）**：写回模式下数据只要进入驱动器 DRAM 即可回复完成，速度快但在掉电时存在丢失脏数据的致命隐患，必须由文件系统日志或显式刷新指令（Flush/FUA）保证持久性。

## 磁盘调度算法

磁盘 I/O 服务时间可形式化表示为：

$$
T_{I/O} = T_{\text{seek}} + T_{\text{rotation}} + T_{\text{transfer}}
$$

由于寻道和旋转在毫秒量级，远大于微秒级的总线传输时间，操作系统和磁盘控制器历来都会通过请求调度优化吞吐量。

### 经典磁道调度：SSTF 与电梯算法

1. **最短寻道时间优先（SSTF / SSF）**：
   - 调度器贪心选择离当前磁头所在磁道最近的请求。
   - **致命缺陷**：如果持续有局部磁道的密集请求到达，远离磁头的边界磁道请求将遭遇永久**饥饿（Starvation）**。
2. **SCAN（扫描算法 / 电梯算法）**：
   - 磁头在磁盘上单一方向扫过（如从内圈向外圈），按顺序处理沿途请求；到达最外侧后反向扫回。
   - **变体 F-SCAN**：在扫描开始时冻结队列，新请求放入下一轮，彻底杜绝局部拥堵导致的饿死；
   - **变体 C-SCAN（循环扫描）**：只沿单向服务请求，到达边缘后磁头以最高速直接飞回起点不处理请求，消除了普通 SCAN 中间磁道服务频率两倍于边缘磁道的不公平性。

### 最短定位时间优先（SPTF）

SCAN 算法虽然消除了饥饿，但它依然不是全局最优，因为它**完全忽略了旋转延迟**。

![SPTF 调度决策情境图：寻道时间与旋转延迟权衡对比](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260327103749054.png)

在如图所示的决策情境中，磁头位于内圈扇区 30。若仅按寻道（磁道距离），中间磁道的扇区 16 似乎更近；但由于旋转滞后，访问扇区 16 需要多等待大半圈旋转。而外侧磁道的扇区 8 尽管磁臂寻道更远，但随着磁臂移动，扇区 8 恰好高速转到磁头下方。

**最短定位时间优先（Shortest Positioning Time First, SPTF / SATF）** 同时计算：

$$
T_{\text{position}} = T_{\text{seek}} + T_{\text{rotation}}
$$

优先调度 $T_{\text{position}}$ 最小的请求。现代硬盘寻道时间（2–8ms）与旋转延迟（4–8ms）处于同一数量级，SPTF 能够带来 30% 到 50% 的吞吐量提升。

由于操作系统只能看到抽象的 LBA 线性地址，无法获知实时的物理微观几何结构和当前主轴旋转相位，**SPTF 必须由现代磁盘控制器内部的固件实现**（依托主机 NCQ / TCQ 队列深度支撑）。

### I/O 合并与预测性调度

- **I/O 合并（I/O Merging）**：操作系统调度器识别出地址相邻的逻辑读写请求（如块 33 与块 34），合并为单一的大块传输命令，削减系统调用开销与请求头封包代价。
- **非工作保持与预测性调度（Anticipatory Scheduling）**：经典调度器属于工作保持型（只要有请求就立即打给驱动器）。但在多进程混合读取场景下，读完一个请求后稍作等待（如 1–2ms），往往能等到同一个进程发出的下一个高度相邻的顺序请求，从而避免磁头被其他随机进程拉离宝贵的顺序磁道。

## 我的理解

::: insight
**机械磁盘是存储系统向物理世界力学定律妥协的终极缩影**：
在纯电子的 CPU 与 DRAM 中，纳秒级的操作让人几乎忘记了物理实体维度的存在。然而机械磁盘却将我们的视野强制拉回宏观物理世界——质量、转动惯量、动量守恒与角速度。寻道过程中的磁臂加速与精准减速、为避免机械震颤引入的稳定延迟，无一不是经典力学的直接投影。
正是因为这种微米级的物理运动成本相比光速电信号过于沉重，整个计算机系统学科才诞生了如此璀璨的软件设计构想：从 Inode 柱面组局部化放置、日志文件系统的批量大顺序写，到 SPTF 旋转感知调度。理解 HDD 的物理机理，才能真正体会存储软件是如何以算法智慧化解物理硬件的先天缺陷。
:::
