# Lec 11 同步器

> 主要文献：Awerbuch《Complexity of Network Synchronization》(JACM 1985) · Awerbuch & Peleg (FOCS 1990) · 对应 Lynch《Distributed Algorithms》第 16 章

## TL;DR

- 同步器（Synchronizer）通过在异步无故障网络上模拟轮次推进，提供了一种将同步算法自动、正确映射到异步环境的通用变换。
- 核心抽象是“安全（Safe）”推进准则：节点收到所有发向邻居的第 $r$ 轮消息确认后即为安全，当且仅当全部邻居安全时方可进入第 $r+1$ 轮。
- 同步器 $\alpha$ 采用全邻居通知实现 $O(1)$ 单轮时间，同步器 $\beta$ 借助生成树收敛广播实现 $O(n)$ 单轮通信，同步器 $\gamma$ 则通过低直径簇分解在时间与通信间取得多项式对数权衡。

## 1. 本讲要回答的核心问题

设计**同步**网络算法（Lec 1–9 的轮模型）通常直观清晰；但现实网络是**异步**的（无全局时钟、消息延迟无界）。

**同步器（synchronizer）** 是一种通用变换：把任意同步算法**自动地、正确地**跑在异步网络上。本讲：

1. 形式化同步器要解决的问题（用 GlobSynch 规约）；
2. 提炼**安全同步器（safe synchronizer）**这一核心抽象；
3. 给出三种实现 **$\alpha$、$\beta$、$\gamma$**，并比较其通信/时间开销；
4. 给出运行同步算法的时间开销下界，及典型应用。

> 注意：同步器不容忍故障——它假定可靠 FIFO 通道、无进程崩溃；目的是**正确性 + 低开销**地模拟同步轮，而非容错。

## 2. 问题：用异步算法实现 GlobSynch

把每个同步进程建模为一个**用户自动机（user automaton）** $U_i$，它通过 `user-send(T,r)` / `user-receive(T,r)` 与外界交换第 $r$ 轮的消息，且满足收发交替、按轮递增。

::: definition 全局同步器 GlobSynch
GlobSynch 在每一轮收集所有 $U_i$ 在 `user-send` 中发出的消息，并在该轮全部 `user-send` 之后、全部 `user-receive` 之前，把消息分发给各 $U_i$。它**全局对齐**每一轮的收发边界。任何同步算法都可写成“用户自动机 + GlobSynch”的组合。
:::

::: definition 同步器问题
用一个**异步**网络算法（每节点一个进程 $P_i$，每条边一对可靠 FIFO 通道）实现 GlobSynch，使得：对任一公平执行 $\alpha$，存在 GlobSynch 系统的公平执行 $\alpha'$，对**每个用户 $U_i$** 都不可区分。
（只需保持**每个用户各自的视图**，不要求保持不同用户事件间的相对全局顺序。）
:::

## 3. 核心抽象：安全同步器

实现 GlobSynch 的难点：进程 $P_i$ 何时可以“进入第 $r+1$ 轮”？关键概念是**安全（safe）**：

::: definition 安全节点（Safe Node）
进程 $P_i$ 在第 $r$ 轮**安全**，当它发出的所有第 $r$ 轮消息都已被邻居**接收并确认（ack）**。
:::

::: theorem 轮次推进规则
$P_i$ 可以安全地进入第 $r+1$ 轮，当且仅当它**所有邻居**都在第 $r$ 轮安全。

*理由：* 同步算法里 $P_i$ 的第 $r+1$ 轮消息只依赖它收到的第 $r$ 轮消息（来自邻居）；若所有邻居都已把第 $r$ 轮消息送达并被确认，则 $P_i$ 已收齐自己第 $r$ 轮的全部输入，可安全推进。
:::

于是三种同步器的全部差别，归结为**如何让每个节点检测到“所有邻居都已安全”**。

## 4. 三种实现

### 4.1 同步器 $\alpha$（Alpha）

> **思想：** 节点一旦安全，就直接通知**所有邻居**“我安全了”；当一个节点收到**全部邻居**的“安全”通知，即进入下一轮。

纯局部，无需任何预处理结构。
- **复杂度（每轮）：** 通信 $C_\alpha=O(|E|)$；时间 $T_\alpha=O(1)$。
- **初始化：** 无。

$\alpha$ 时间最优，但通信随边数膨胀——在稠密图上昂贵。

### 4.2 同步器 $\beta$（Beta）

> **思想：** 预先建一棵**有根生成树**（带领袖）。安全信号沿树**收敛广播**上传：叶到根逐层报告“我及子树全部安全”；根收齐后沿树**广播**下发“全网本轮安全，开始下一轮”。

- **复杂度（每轮）：** 通信 $C_\beta=O(n)$（只用树边）；时间 $T_\beta=O(\text{树高})=O(\mathrm{diam})$。
- **初始化：** 需构造生成树 + 选领袖。

$\beta$ 通信最省，但时间随树高膨胀——在长链拓扑上昂贵。

### 4.3 同步器 $\gamma$（Gamma）

> **思想：** 把图划分成若干**低直径簇（cluster）**，并在簇间选定**优先边**连成簇间结构。**簇内用 $\beta$**（树上收敛广播/广播），**簇间用 $\alpha$**（相邻簇沿优先边互相通知）。

用参数 $k$ 调节簇的大小，在 $\alpha$ 与 $\beta$ 之间连续插值：
- **复杂度（每轮）：** 通信 $C_\gamma=O(k\cdot n)$；时间 $T_\gamma=O(\log_k n)$。

::: example 同步器开销权衡对比
模拟一个 $T$ 轮、$M$ 消息的同步算法：
- $\alpha$：时间 $O(T)$，通信 $O(M+T\cdot|E|)$；
- $\beta$：时间 $O(T\cdot\mathrm{diam})$，通信 $O(M+T\cdot n)$；
- $\gamma$：时间 $O(T\log_k n)$，通信 $O(M+T\cdot k n)$。

$\gamma$ 表明：借助低直径簇分解，可以同时把时间压到多项式对数、通信压到近线性——这正是 Awerbuch 网络同步理论的核心成果。
:::

## 5. 时间开销下界

同步器不是免费的：

> **定理（粗述）.** 若要求很强的同步（每个节点的逻辑时间与实时严格对齐），则在异步网络上运行同步算法必然带来 $\Omega(\mathrm{diam})$ 量级的时间开销。

直觉：把“全局对齐第 $r$ 轮边界”做到精确，等价于一次全网协调，而全网协调至少要让信息穿过网络直径。$\gamma$ 之所以能做到 $O(\log_k n)$ 而不撞这个下界，是因为它只保证每个用户各自视图正确，并不强求不同用户间的全局实时对齐。

## 6. 典型应用

把同步器套在已有同步算法外，立刻得到异步版本：
- **领袖选举**、**广度优先搜索 (BFS)**、**最短路**：直接复用 Lec 2 的同步原语；
- **广播与确认**；
- **最大独立集 (MIS)**：复用 Lec 5 的同步随机算法。

## 7. 本讲小结与同步器权衡

| 同步器 | 每轮通信 | 每轮时间 | 初始化 | 思想 |
|---|---|---|---|---|
| $\alpha$ | $O(\lvert E\rvert)$ | $O(1)$ | 无 | 全邻居通知 |
| $\beta$ | $O(n)$ | $O(\mathrm{diam})$ | 生成树+领袖 | 树上收敛广播/广播 |
| $\gamma$ | $O(kn)$ | $O(\log_k n)$ | 簇分解 | 簇内 $\beta$ + 簇间 $\alpha$ |

主线：**“安全”是统一抽象**（节点安全 ⇒ 邻居皆安全才推进），三种同步器只是传播安全信号的三种策略；$\gamma$ 借**低直径簇分解**在时间与通信间取得 polylog 折中，与网络分解（Lec 6–7）一脉相承。
