# Lec 1 课程概览与区间调度（Overview & Interval Scheduling）

## TL;DR

- **计算复杂性全景**：区分多项式时间可解的 P 类、多项式时间可验证的 NP 类，以及最难的 NP 完全问题（NPC）。
- **无权区间调度**：基于“最早完成时间优先”（Earliest Finish Time First）策略，通过拟置换法（Exchange Argument）严格证明贪心解的全局最优性。
- **带权区间调度**：贪心选择失效后转为动态规划（DP），结合二分搜索查找前驱兼容区间，将复杂度由 $O(n^2)$ 优化至 $O(n \log n)$。
- **区间划分与多机器调度**：区间深度（Depth）构成了资源需求的刚性理论下界，按开始时间排序的贪心着色策略能以恰好 $d$ 台机器完成全量无冲突调度。

---

## 计算复杂性导引：P、NP 与 NP 完全性

在算法设计中，极为相似的问题描述可能对应天壤之别的计算复杂度：

::: definition
**P（Polynomial Time）**
在确定性多项式时间内可判定的判定问题集合，即存在常数 $k$ 使得算法运行时间在 $O(n^k)$ 之内。例如：单源最短路径（Dijkstra / Bellman-Ford，复杂度 $O(|V|^2)$ 或 $O(|E| + |V| \log |V|)$）、欧拉回路判定（线性时间）。
:::

::: definition
**NP（Nondeterministic Polynomial Time）**
在多项式时间内其实例解答**可被验证**（Verifiable）的判定问题集合。若给定一个解的候选凭据（Certificate），可在 $O(n^k)$ 时间内核验其有效性。例如：哈密顿回路判定（验证给定路径是否恰好访问每个顶点一次极为简单）。
:::

::: definition
**NP 完全性（NP-Complete）**
问题属于 NP 类，且 NP 中的任意问题均可在多项式时间内归约至该问题。若任意一个 NP 完全问题存在多项式时间算法，则 $P = NP$。
:::

## 无权区间调度与贪心选择

### 问题形式化定义

给定单个共享资源与 $n$ 个请求构成的集合 $R = \{r_1, r_2, \dots, r_n\}$。每个请求 $r_i = [s(i), f(i))$ 包含起始时间 $s(i)$ 与结束时间 $f(i)$，满足 $s(i) < f(i)$。

若两请求 $i, j$ 互不重叠，即 $f(i) \le s(j)$ 或 $f(j) \le s(i)$，则称它们是**兼容的（Compatible）**。

![区间请求时间线与重叠示意图](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66acce35f1bb1.png)

- **优化目标**：选出一个两两兼容的请求子集 $S \subseteq R$，使得子集规模 $|S|$ 最大。

### 贪心启发式规则尝试与反例分析

贪心算法每次依据局部启发式准则选择一个区间 $i$，剔除所有与其冲突的重叠请求，直到无可用区间。核心在于选取何种选择规则：

1. **尝试 1：最早开始时间优先（Minimum $s(i)$）**
   - *反例*：若存在一个超长区间跨越全局（例如 $[0, 100)$），但内部存在数十个短区间，优先选择最早开始者将导致其余所有短区间被拒绝。
2. **尝试 2：最短持续时间优先（Minimum $f(i) - s(i)$）**
   - *反例*：短区间可能横跨两个非重叠区间之间的间隙，导致选 1 弃 2。

   ![最短持续时间贪心选择的反例示意](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66ad090b98381.png)

3. **尝试 3：最少冲突次数优先（Minimum Incompatible Count）**
   - *反例*：在特定结构中，选择当前局部冲突最小的区间，可能会破坏后续多组更大规模的无冲突序列。

   ![最少冲突次数贪心选择的反例示意](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66ad09928d3d8.png)

4. **尝试 4：最早完成时间优先（Earliest Finish Time First）**
   - *策略*：在当前候选集合中，选择 $f(i)$ 最小的请求。直觉在于：越早结束，为后续保留的可用时间窗口就越大。

### 贪心最优性数学证明

::: theorem
**最早完成时间贪心算法的最优性**
设贪心算法按最早完成时间产出的调度为 $S = \langle i_1, i_2, \dots, i_k \rangle$，最优调度为 $S^* = \langle j_1, j_2, \dots, j_{k^*} \rangle$。则必然有 $k = k^*$。
:::

**证明（归纳法与置换论证 Exchange Argument）**：

1. **基本情况**：当 $k^* = 1$ 时，由于至少可选 1 个，贪心解 $k \ge 1$，故 $k = 1 = k^*$ 显然成立。
2. **归纳假设**：假设对于任意最优规模为 $k^*$ 的子问题，贪心算法均能返回最优解。
3. **归纳步骤**：考虑规模为 $k^* + 1$ 的最优调度序列 $S^*$：
   $$
   S^* = \langle j_1, j_2, \dots, j_{k^*+1} \rangle
   $$
   贪心算法第一步选取的区间为 $i_1$。根据贪心选择准则：
   $$
   f(i_1) \le f(j_1)
   $$
   由于 $j_1$ 仅与 $S^*$ 中的自身冲突，且 $j_2$ 的起始时间满足 $s(j_2) \ge f(j_1) \ge f(i_1)$，因此区间 $i_1$ 与 $j_2, j_3, \dots, j_{k^*+1}$ 全部兼容！

   我们构造新调度 $S^{**}$：
   $$
   S^{**} = \langle i_1, j_2, j_3, \dots, j_{k^*+1} \rangle
   $$
   $S^{**}$ 依然由 $k^* + 1$ 个两两兼容的区间组成，故 $S^{**}$ 亦为最优调度。

   现在定义剩余问题空间 $L' = \{r \in R \mid s(r) \ge f(i_1)\}$。因为 $S^{**}$ 在全局最优，所以其后继序列 $\langle j_2, \dots, j_{k^*+1} \rangle$ 必须是子问题 $L'$ 的最优调度（规模为 $k^*$）。

   根据归纳假设，贪心算法在 $L'$ 上必定能找到规模为 $k^*$ 的解。由于贪心算法在选定 $i_1$ 后正是严格在 $L'$ 上继续执行并产出 $\langle i_2, \dots, i_k \rangle$，因此：
   $$
   k - 1 = k^* \implies k = k^* + 1
   $$
   证毕。

## 带权区间调度与动态规划

当每个请求带有独立权值 $w(i) > 0$ 时，贪心准则立刻失效（极早结束的区间可能权值极微，而略长区间收益极高）。此时须转用**动态规划（Dynamic Programming）**。

### 子问题形式化与状态转移

将请求集合按结束时间升序预排序：$f(1) \le f(2) \le \dots \le f(n)$。

对每个请求 $j$，定义其**前驱兼容区间索引** $p(j)$：
$$
p(j) = \max \{i < j \mid f(i) \le s(j)\} \quad (\text{若不存在则 } p(j) = 0)
$$

对于第 $j$ 个区间的子问题 $\mathrm{OPT}(j)$，决策仅有两种：
1. **不选第 $j$ 个区间**：收益为 $\mathrm{OPT}(j-1)$；
2. **选择第 $j$ 个区间**：获得收益 $w(j)$，其前面不可包含任何重叠区间，因此前置最优只能延伸至 $p(j)$，总收益为 $w(j) + \mathrm{OPT}(p(j))$。

状态转移方程如下：
$$
\mathrm{OPT}(j) = \max\Big(\mathrm{OPT}(j-1), \, w(j) + \mathrm{OPT}(p(j))\Big)
$$
边界条件为 $\mathrm{OPT}(0) = 0$。

### 复杂度优化：从 $O(n^2)$ 到 $O(n \log n)$

- 若每次线性查找 $p(j)$，计算前驱需要 $O(n)$，状态计算总耗时为 $O(n^2)$。
- 由于所有区间按结束时间 $f(i)$ 有序排列，利用**二分搜索（Binary Search）**查找满足 $f(i) \le s(j)$ 的最大下标只需 $O(\log n)$。
- 排序耗时 $O(n \log n)$，预处理所有 $p(j)$ 耗时 $O(n \log n)$，DP 填表耗时 $O(n)$，整体运行时间严格控制在 $O(n \log n)$。

## 区间划分与多机器调度

若任务无法丢弃，但允许多台相同的机器并行处理，如何使用最少的机器容纳所有请求？

::: definition
**区间深度（Interval Depth）**
在一组区间 $R$ 中，任意时刻 $t$ 覆盖该时刻的区间集合的最大重叠数称为该区间集的深度 $d$：
$$
d = \max_{t} \big|\{i \in R \mid s(i) \le t < f(i)\}\big|
$$
:::

显然，任何调度方案至少需要 $d$ 台机器（因为在重叠峰值处有 $d$ 个互不兼容的请求必须同时占用不同机器）。

### 贪心着色算法

1. 将所有请求按**起始时间**递增排序：$s(1) \le s(2) \le \dots \le s(n)$；
2. 依次遍历每个区间 $i$：
   - 检查已有机器中是否存在当前空闲的机器（即机器上最后一个区间的结束时间 $\le s(i)$）；
   - 若存在，分配至该机器；
   - 若所有机器均处于忙碌状态，开辟一台新机器并分配给区间 $i$。

::: theorem
**多机器区间划分的最优性**
上述按起始时间排序的贪心算法所分配的机器总数恰好等于区间深度 $d$，因此在机器数量上全局最优。
:::

**证明**：
假设算法分配了第 $k$ 台机器给区间 $i$。这意味着在考虑区间 $i$ 时，已存在的 $k - 1$ 台机器全部处于忙碌状态，即每台机器上都有一个区间的结束时间晚于 $s(i)$。同时，由于所有区间是按起始时间遍历的，这 $k - 1$ 台机器上的活动区间起始时间必然 $\le s(i)$。

因此，在时刻 $s(i)$，连同区间 $i$ 本身在内，共有至少 $k$ 个区间彼此重叠并覆盖时刻 $s(i)$。根据深度的定义，必然有 $d \ge k$。又因为算法终止时最大机器编号不会超过任何时刻检测到的重叠数，故最大机器数 $\le d$。二者结合得到所需机器数恒等于 $d$。

使用优先队列（小根堆）维护每台机器的最早可用时间，整体算法复杂度为 $O(n \log n)$。

## 我的理解

::: insight
区间调度是领悟“算法策略谱系”的最经典切片：
1. **贪心选择的本质是空间压缩**：无权区间调度之所以可以用贪心解决，是因为所有区间的收益权值完全等价，算法只需在时间轴上“尽可能紧凑地排列”，最早完成时间优先就是让未决时间资源最大化的保全策略。
2. **权值打破拟阵，DP 接管全局**：一旦引入权重，局部极早完成不再蕴含全局最优，局部贪心彻底失效。此时必须利用区间单向演进的时间箭头建立子问题拓扑序，动态规划通过“选或不选”的完备分支与二分查找，在多项式时间内穷尽了状态演化路径。
3. **资源扩容的对偶之美**：单机器调度关注“在固定资源下最大化吞吐”，多机器调度关注“在固定需求下最小化资源”。区间深度 $d$ 既是下界障碍，又是按起始时间贪心所能达到的精确上界，体现了组合优化中强对偶定理的雏形。
:::
