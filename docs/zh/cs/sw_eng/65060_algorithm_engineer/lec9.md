# Lec 9 高性能并行排序算法（High-Performance Parallel Sorting: Sample Sort & Radix Sort）

## TL;DR

- **现代排序算法的瓶颈演变**：在大规模现代多核架构上，排序的主要开销已由传统的“元素比较次数”全面转移为**分支预测失败惩罚（Branch Mispredictions）**与**随机跨核访存延迟（DRAM Access）**。
- **无分支超级标量采样排序（SSSS）**：通过精心构造的无分支条件传送（CMOV）扁平决策树，同时切分 $k$ 个桶，完全消除了处理器的流水线分支预测惩罚。
- **IPS4o 与就地并行化（In-Place Engineering）**：以 IPS4o 为代表的工业级前沿算法，通过小容量本地块缓冲（Block Buffers）与置换循环分解，以纯就地（In-Place）常数级辅助空间达成了超越经典库函数数倍的吞吐。

## 排序算法的微架构现实

在大学初阶算法课程中，排序的复杂度分析建立在“元素比较次数”的模型之上：比较排序的最坏情况理论下界为 $\Omega(n \log n)$。

然而在现代超标量处理器上，这种纯数学模型会导致极其糟糕的工程决策：
1. **分支预测失败的巨大惩罚**：快速排序在每次进行 `if (A[i] < pivot)` 时，如果输入数据分布随机，分支预测的错误率将接近 50%。在 Skylake 或 Zen 架构中，每次分支预测失败需要清空长达 14~20 级的流水线，付出数十个时钟周期的空耗。
2. **额外内存分配与带宽枯竭**：传统的归并排序或经典基数排序（Radix Sort）需要分配一个与输入规模相同的大数组作为辅助中转空间（Out-of-Place）。当数据规模达到几十 GB 时，分配与释放大块虚拟内存将引发海量 Page Fault，且在多核写入时直接打爆主存总线带宽。

## 超级标量采样排序（Super Scalar Sample Sort, SSSS）

传统的快速排序每次仅选择一个主元（Pivot）将数据划分为两个子集。为了充分利用现代多核处理器的宽向量寄存器与深层流水线，**采样排序（Sample Sort）**每次同时选择 $k-1$ 个主元，将数据一次性分流至 $k$ 个桶中（通常取 $k = 256$ 或 $k = 1024$）。

### 无分支扁平决策树（Branch-Free Decision Tree）

Sanders 与 Winkel 在 2008 年提出了超级标量采样排序（SSSS）。其核心创新在于：**如何不用任何 `if` 条件分支，将元素 $x$ 分流到 $k$ 个桶中的正确一个？**

我们将 $k-1$ 个主元排列为一个深度为 $d = \log_2 k$ 的静态完全二叉搜索树（保存在一个紧凑的数组中）：
- 根节点为主元 $P_1$，左孩子为 $P_2$，右孩子为 $P_3$，以此类推。

对于待分类的任意元素 $x$，分类过程被展开为一段严格由**条件传送指令（Conditional Move, CMOV）**驱动的扁平循环：

```c
// 扁平二叉树无分支寻址 (k = 16, 深度为 4)
int b = 1;
for (int level = 0; level < d; level++) {
    // 利用硬件指令 (x > P[b]) 产出 0 或 1，无任何条件跳转指令
    b = 2 * b + (x > P[b]);
}
int bucket_id = b - k;
```

由于代码中没有任何跳转（Jump/Branch）指令，CPU 的超标量流水线可以以极限吞吐无阻碍全速前进，单核指令吞吐率（IPC）可高达 3.5 以上，彻底消除了分支预测失败的微架构陷阱！

## 就地并行基数排序（Parallel In-Place Radix Sort）

对于整数键值，基数排序在理论上可以在 $O(n \cdot \frac{w}{b})$ 时间内完成排序，其中 $w$ 为整数位宽，$b$ 为单次处理的块位宽。

但传统基数排序最大的工程痛点在于**非就地性（Out-of-Place）**：它必须为每个阶段分配辅助数组。Julian Shun 等人在 2013 年提出了 **Regions Sort**，随后学术界衍生出了著名的 **PARADIS** 算法。

### 局部块交换与环形置换机制

1. **局部直方图统计**：每个核心并发扫描自己分配的输入数据切片，统计每个基数桶的局部直方图；利用我们在 Lec 2 学习的**并行前缀和（Parallel Scan）**，全局精确计算出每个桶在原数组中的绝对边界。
2. **块级中转缓冲区（Block Buffers）**：每个核心申请极小规模的本地线程私有缓冲区（例如 256 字节）。当核心从当前位置读取元素时，先将其放入目标桶的私有小缓冲区中。
3. **全局就地置换环**：当小缓冲区填满一个完整的缓存行时，将其原子写入目标桶对应的槽位，并将原槽位的未分类数据调换出来，在原数组内部形成封闭的**就地置换环（In-Place Permutation Cycles）**。这完全消除了分配全局辅助大数组的必要性。

## IPS4o：现代排序算法的巅峰之作

2017 年，Axtmann 等人融合了 SSSS 的无分支特性与就地块置换技术，提出了 **IPS4o（In-Place Parallel Super Scalar Sample Sort）**。

```text
       输入数组 A: [  Block 0  ][  Block 1  ] ... [  Block M  ]
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
        Worker 1 (无分支分桶)        Worker 2 (无分支分桶)
        私有 Block Buffer           私有 Block Buffer
             │                           │
             └─────────────┬─────────────┘
                           ▼
                  (全局就地置换环回写)
```

IPS4o 的工程精髓：
- **两级分桶设计**：自适应根据多核的 L1/L2 缓存容量调整主元数量，保证扁平主元树与当前正在填充的块缓冲区始终驻留在高速 L1 缓存内。
- **尾部递归自适应退化**：当子问题规模缩小到数百个元素时，自动平滑退化为单核排序网络（Sorting Networks）或插入排序，规避递归基调用的调用栈开销。
- **实测表现**：在多核机器上，IPS4o 的排序速度比 C++ 标准库 `std::sort` 快 10 倍以上，比经典 Intel TBB 库的 `parallel_sort` 快 3~5 倍，成为了现代数据库与大数据分析引擎的首选底层排序原语。

::: insight 排序算法的工程启示：理论复杂度的终点正是体系结构优化的起点
经典计算机科学教程常常给人一种错觉：既然快速排序的复杂度已经证明为 $O(n \log n)$ 且基数排序为 $O(n)$，排序问题就已经在理论上终结了。然而算法工程的实践表明，具有完全相同 $O(n \log n)$ 复杂度的两个算法，其真实运行时间由于**分支预测命中率、指令级并行度与缓存局部性**的差异，可以拉开整整一个数量级的鸿沟。从 SSSS 的无分支二叉树到 IPS4o 的就地缓存块环形调度，算法工程展示了如何将底层的汇编指令特性（CMOV）与宏观的代数数据结构天衣无缝地交融在一起。
:::
