# 能力连续谱与统一 Web 设计

## 问题情境

在许多产品研发团队中，无障碍（Accessibility / A11y）和包容性设计常常被视为边缘化的“慈善附加项”：
- 团队常常推诿：“我们的目标用户都是健全的年轻人，不需要浪费工时支持盲人读屏器”；
- 当需要支持阿拉伯语或希伯来语等从右向左（RTL）书写的国际化市场时，工程师不得不维护两套完全重复、充斥着 `left` 与 `right` 翻转补丁的 CSS 代码库；
- 当用户在强烈的户外阳光下查看手机、单手抱着婴儿提着重物操作手机，或者在安静的图书馆里没有佩戴耳机时，原本看似“现代化”的界面瞬间变得无法使用。

这种困境源于对“人类能力”的狭隘静态假设。将用户人为割裂为“正常人”与“残障人士”，在人机交互与认知工程上被证明是一种极其昂贵且错误的偏见。

## 概念界定

::: definition [能力连续谱（The Ability Spectrum）与统一 Web 设计（Universal Design）]
- **统一 Web 设计（Universal Web Design）**：万维网创始人蒂姆·伯纳斯-李（Tim Berners-Lee）确立的万维网核心宪章——“Web 的力量在于它的普遍性。无论残障与否，所有人都能访问是其本质所在（This is for everyone）”。它要求设计从根基上具备弹性和容纳度，无需定制或适配即可被所有人使用；
- **能力连续谱模型（The Ability Spectrum）**：由微软包容性设计实验室（Microsoft Inclusive Design）提出。该模型指出：**残障并不是孤立的个人身体缺陷，而是人类身体与不合理设计的物理/数字环境之间发生的失配错位（Mismatch）**。人类的身体与认知能力不是非黑即白的二元状态，而是一个动态变化的广谱区间。
:::

包容性设计不是为了少数边缘群体的慈善妥协，而是创造出能惠及全体人类在极端情境下稳定运行的卓越工程体系。

## 解释与依据

### 1. 能力失配的三种维度：永久、暂时与情境

微软能力连续谱将功能障碍解构为三种等效的情境形态：

| 感官 / 运动通道 | 永久性障碍（Permanent） | 暂时性障碍（Temporary） | 情境性障碍（Situational） |
| :--- | :--- | :--- | :--- |
| **触觉 / 上肢运动** | 先天缺失一只手臂（约占 0.05%） | 手臂骨折打着石膏缠着绷带 | 抱养婴儿或单手提着沉重的杂物箱 |
| **视觉通道** | 完全失明或重度白内障 | 做完近视激光手术散瞳尚未恢复 | 在强烈的夏季户外日光直射下看屏幕 |
| **听觉通道** | 先天全聋或重度听力衰退 | 患严重中耳炎导致暂时失聪 | 处于机场候机室或无耳机的极安静图书馆 |
| **言语 / 交流通道** | 无法发声的哑音障碍 | 患急性喉炎咽喉红肿失声 | 处于嘈杂的地铁车厢或要求噤声的会议室 |

```text
[永久性群体: ~10万人] ──── 驱动无障碍基线规范 (如读屏器与键盘导航)
         ^
         |
[暂时性群体: ~100万人] ──── 显著扩大受益面 (如手骨折患者依然能单手快捷键生产)
         ^
         |
[情境性群体: ~1000万人] ─── 惠及全体普罗大众 (如户外强光对比度、单手防误触热区)
```

**工程启示**：当你为了失明用户精心编写了语义化 HTML 标题层级和图片 `alt` 文本时，你不仅拯救了读屏器用户，同时瞬间为全网搜索引擎蜘蛛（SEO）、弱网环境下图片加载失败的普通用户，以及智能音箱语音导航打通了全部数据通道。

### 2. WCAG 2.2 核心四大支柱：POUR 原则

W3C 制定的《Web 内容无障碍指南》（WCAG）围绕四大不可妥协的人机交互维度建立：

1. **可感知性（Perceivable）**：信息与 UI 控件必须能通过用户的多种感官通道被感知（非纯文本必须有文字替代，音频必须有字幕，正文具备至少 4.5:1 的感知对比度）；
2. **可操作性（Operable）**：所有交互功能必须支持纯键盘无障碍导航（无键盘陷阱，具备清晰的 `:focus-visible` 轮廓），留出充足的阅读与交互时间，严禁包含会诱发光敏性癫痫的高频闪烁（每秒闪烁不得超过 3 次）；
3. **可理解性（Understandable）**：文字内容清晰可读，输入交互具备高度可预测性（表单字段具有显式 `<label>` 绑定，提交错误时提供具象的人类可读修正指引）；
4. **稳健性（Robust）**：内容能够被广泛的用户代理（包括当前与未来的现代浏览器、移动辅助设备与读屏软件）稳定且无歧义地解析，严格遵循语义化 HTML 语法。

### 3. CSS 逻辑属性（Logical Properties）与多语言流向

传统 Web 布局基于西方物理方向绑定（`left`, `right`, `top`, `bottom`）。当网页需要出海适配阿拉伯语、希伯来语（从右向左 RTL）或传统日文竖排文本时，硬编码的物理方向会导致严重的视觉错乱。

现代 W3C 逻辑属性将坐标系彻底抽象为两条正交维度：
- **行内维度（Inline Dimension）**：沿着文字书写的方向（在 LTR 英文/中文中为从左到右；在 RTL 阿拉伯文中为从右向左；在竖排中为从上到下）；
- **块级维度（Block Dimension）**：沿着段落堆叠的方向（通常为从上到下）。

| 传统物理属性（已过时） | 现代逻辑属性（推荐标准） | 在 LTR（中文/英文）中的行为 | 在 RTL（阿拉伯语）中的自适应行为 |
| :--- | :--- | :--- | :--- |
| `margin-left` | `margin-inline-start` | 左外边距 | **自动镜像为右外边距**（无需任何额外代码） |
| `margin-right` | `margin-inline-end` | 右外边距 | **自动镜像为左外边距** |
| `padding-top` | `padding-block-start` | 上内边距 | 上内边距 |
| `width` | `inline-size` | 水平宽度 | 水平宽度（在竖排模式下自动变垂直高度） |
| `text-align: left` | `text-align: start` | 左对齐 | **自动变为右对齐** |

## 边界与辨析

### 1. 语义化 HTML vs 随意 `<div>` + `aria-*` 补丁

很多开发者习惯用纯 `<div>` 搭建一切界面，遇到无障碍审计时才匆忙贴上一大堆 `aria-label`、`role="button"`、`tabindex="0"` 和手写键盘监听。
- **第一无障碍规则（First Rule of ARIA）**：
  > “如果可以使用原生语义 HTML 元素（如 `<button>`, `<dialog>`, `<nav>`, `<input>`）实现相应功能，**绝对不要使用 ARIA 属性进行模拟**。”
- **原生优势**：原生语义标签免费内置了可供性声明、键盘 Tab 聚焦管理、回车/空格键激活行为以及无障碍树（Accessibility Tree）的底层原生映射。

### 2. 文字膨胀（Text Expansion）与自适应容器

不同人类语言表达相同语义时所消耗的字符长度差异极大。通常德语、俄语相比英语会膨胀 30% 至 50%，而中文相对更为紧凑。
- **坏设计**：为按钮或卡片硬编码固定宽度（如 `width: 120px`）和固定高度，导致翻译后的多语言文字发生截断重叠；
- **自适应设计**：使用内边距驱动的自适应尺寸（如 `min-width` 配合内容自撑开），保证界面在全球化语言下优雅延展。

::: insight
无障碍不是让设计变得丑陋或枯燥。最顶级的设计——如高对比度深色模式、大尺寸触控热区、清晰易读的字号阶梯、优雅的键盘快捷键——在改善残障人士体验的同时，无一例外地让所有健全用户的体验得到了质的跃升。
:::

## 提取与迁移

- **在包容性表单设计中**：
  摒弃对人类名字的偏见（如强制要求“名”和“姓”分成两栏、禁止单字姓名、禁止连字符或非拉丁字符）。直接使用单一文本框 `姓名`，并允许任意合法的 Unicode 字符输入；
- **在系统级用户偏好监听中**：
  使用现代 CSS 媒体查询响应用户的生理偏好配置：
  ```css
  @media (prefers-reduced-motion: reduce) {
    /* 尊重前庭神经失调患者，关闭所有剧烈翻转与位移动画 */
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```

## TL;DR

- 能力连续谱模型揭示：残障并非个体缺陷，而是环境设计与人类身体能力的动态错位；永久性、暂时性与情境性障碍共享相同的人机交互瓶颈。
- WCAG POUR 四大原则（可感知、可操作、可理解、稳健）确立了全球通用的无障碍工程底线。
- CSS 逻辑属性（如 `margin-inline-start`、`inline-size`）将排版从物理方向解耦，零成本支撑从左向右（LTR）与从右向左（RTL）多语言自适应布局。
