# 知觉均匀色彩空间与 APCA 对比度

## 问题情境

在现代 UI 设计系统与动态主题（Design Systems & Theming）的构建中，工程师与设计师长期饱受一套“色彩数学谎言”的折磨：
- 当试图使用传统的 HSL（色相、饱和度、亮度）模型为设计系统生成一组不同色调的状态色（如警告黄、成功绿、危险红、信息蓝）时，开发者设定它们具有完全相同的亮度 `50%`；然而呈现在屏幕上，纯黄色（`hsl(60, 100%, 50%)`）耀眼刺目、几乎无法搭配白底文字，而纯蓝色（`hsl(240, 100%, 50%)`）却深沉如黑夜；
- 当按照 WCAG 2.1 官方推荐的相对亮度公式计算出 `4.5:1` 对比度时，细体小号文字在黑底白字下发生了严重的光晕发散（Halation），视力轻度退化的读者依然无法看清；
- 现代智能手机和 MacBook 屏幕普遍支持绚丽的 Display P3 广色域，但老旧的 `rgb()` 语法却将色彩死死锁在 30 年前笨重 CRT 显示器的狭窄 sRGB 牢笼中。

这些工程痛点揭示了一个核心矛盾：**面向计算机硬件发光的颜色模型，根本不符合人类大脑视神经的真实生理感知机制**。

## 概念界定

::: definition [知觉均匀色彩空间（Perceptually Uniform Color Space）与 APCA]
- **知觉均匀色彩空间（Perceptually Uniform Color Space）**：指空间内任意两点之间的几何距离，严格等比例对应于人类肉眼所感知到的主观色差（如 CIELAB、LCH 以及现代的 **OKLCH**）。在 OKLCH 中，明度分量 $L$ 严格独立于色相 $H$，相同的 $L$ 绝对保证人类视觉明暗感知的一致性；
- **高级知觉对比度算法（APCA / Advanced Perceptual Contrast Algorithm）**：拟定作为 WCAG 3 核心标准的新一代对比度模型。基于人类神经生理学与空间对比敏感度函数（CSF），将文本的**空间频率（字号与字重）**、**极性（暗底亮字 vs 亮底暗字）**与**知觉明度**深度结合，输出连续的对比度阶值 $L^c$。
:::

OKLCH 解决了“如何科学客观地生成颜色”，APCA 解决了“如何精准量化文本在复杂背景下的可读性”。

## 解释与依据

### 1. 传统模型（sRGB / HSL）的知觉扭曲剖析

人眼视网膜对不同波长光线的能量感知极度偏斜。根据光度函数（Luminosity Function $V(\lambda)$），人眼对 555nm（黄绿色）最为敏感，而对红蓝两端极不敏感。

```text
感知明度 (Perceived Lightness)
 100% |        .---. [纯黄: 感知明度 ~93%]
  80% |       /     \
  60% |      /       \
  40% |     /         \
  20% |    /           '---. [纯蓝: 感知明度 ~26%]
    0 +--------------------------------------------> 色相环角度
      0° (红)  60° (黄) 120° (绿) 240° (蓝) 360°
      * 注意：在传统 HSL 中，这些纯色的 L 均为 50%！
```

- **HSL 的数学欺骗性**：HSL 仅仅是对 sRGB 硬件立方体做了一个生硬的圆柱体几何投影。它的所谓“$L$”只是纯红、纯绿、纯蓝通道强度的最大最小值平均数 $\frac{\max(R,G,B) + \min(R,G,B)}{2}$，根本没有考虑人眼视网膜对不同颜色的敏感度差异；
- **后果**：在 HSL 中仅改变色相 $H$（保持 $S$ 和 $L$ 不变），界面的实际视觉明度和可读对比度会发生戏剧性的崩溃。

### 2. 现代革命：OKLCH 的正交物理架构

由 Björn Ottosson 于 2020 年发布、并被 W3C 写入 CSS Color 4 / 5 标准的 **OKLCH**，由三个正交的物理分量构成：

```css
/* 现代 CSS OKLCH 语法 */
color: oklch(0.7 0.15 145deg);
```

1. **$L$（Perceived Lightness，感知明度）**：`0%`（黑）至 `100%`（白）。**具有坚固的知觉均匀性**。`oklch(70% 0.2 60)` 与 `oklch(70% 0.2 240)` 在人类眼中具有绝对一致的视觉亮度和对比度；
2. **$C$（Chroma，彩度）**：从 `0`（灰度）到显示器硬件支持的极限（P3 屏幕可达约 `0.37`）。数值大小严格对应人类感知到的色彩鲜艳度；
3. **$H$（Hue Angle，色相角）**：0° 至 360° 的平滑色相环，消除了 CIELAB 历史遗留的“蓝色移向紫色时发生的色相偏移（Abney Effect）”。

### 3. 对比度算法的代际演进：WCAG 2.1 vs APCA

| 评估维度 | 传统 WCAG 2.1 对比度算法 | 新一代 APCA（WCAG 3 提案） |
| :--- | :--- | :--- |
| **数学模型** | 基于简单相对亮度比：$\frac{L_1 + 0.05}{L_2 + 0.05}$ | 基于神经生理学非线性幂律响应与光感受器漂白模型 |
| **字号与字重** | **粗暴脱节**：仅机械划分为“大字”与“普通字”两档 | **深度耦合**：为 12px 细体、16px 正文、32px 粗体分别计算不同的 $L^c$ 达标线 |
| **极性对称性** | **完全对称**（白底黑字与黑底白字计算数值完全相同） | **非对称感知**：识别黑底白字时人眼晶状体的光晕发散（Halation），调高暗色模式下的对比度门槛 |
| **输出指标** | 无量纲比值（$1:1$ 至 $21:1$），要求正文 $\ge 4.5:1$ | $L^c$ 连续分数（$-108$ 至 $+106$），正文通常要求 $|L^c| \ge 60 \sim 75$ |

## 边界与辨析

### 1. 广色域（Display P3）与色域裁剪（Gamut Mapping）

- **Display P3 优势**：现代 iPhone、iPad、MacBook 及高素质 Android 设备支持 Display P3 广色域，比老旧 sRGB 多包含约 50% 的色彩容积，能呈现极度鲜艳的荧光绿和深红；
- **色域裁剪风险**：如果使用 OKLCH 设置了一个极高的彩度（如 `oklch(70% 0.35 140)`），在 P3 屏幕上能完美呈现，但在普通 sRGB 廉价显示器上超出了硬件物理极限；
- **现代浏览器解决方案**：现代浏览器原生实现了 **OKLCH 色域映射（Gamut Mapping）**——在保持感知明度 $L$ 和色相 $H$ 绝对不变的前提下，仅沿着水平轴微调压缩彩度 $C$，使颜色平滑落在目标屏幕的物理边界内，杜绝了传统色彩空间直接截断（Clipping）引发的变色偏色灾难。

### 2. 调色盘自动生成公式：单变量派生

在传统设计系统中，为浅色与深色模式维护数十个十六进制（Hex）颜色值既耗费人力又容易发生对比度不达标。

利用 OKLCH 的正交特性，开发者只需指定一个品牌主色相（`--brand-h`）和一个基础彩度（`--brand-c`），就能通过纯 CSS 变量数学派生出整套在任何色相下均自洽达标的完整调色系统：

```css
:root {
  /* 定义品牌主色调：220deg 对应冷蓝色，彩度控制在舒适无刺激的 0.16 */
  --brand-h: 220deg;
  --brand-c: 0.16;

  /* 背景色：超高明度 98%，微弱混入品牌色相避免纯白刺目 */
  --bg-surface:       oklch(98% 0.01 var(--brand-h));
  /* 正文文字：深沉明度 20%，与背景形成近 80% 的绝对感知落差，远超 WCAG AAA 级要求 */
  --text-primary:     oklch(20% 0.02 var(--brand-h));
  /* 主交互按钮：中度明度 60% 配合饱满彩度，视觉吸睛但绝不耀眼 */
  --accent-button:    oklch(60% var(--brand-c) var(--brand-h));
  /* 悬停微状态：精确下压 8% 的感知明度，提供立竿见影的点击反馈 */
  --accent-hover:     oklch(52% var(--brand-c) var(--brand-h));
}
```

当品牌升级需要将全站从“科技蓝”切换为“森林绿”或“活力橙”时，工程师只需修改一行代码 `--brand-h: 140deg;`。所有界面的层次关系、文字可读性与无障碍对比度依然严丝合缝，彻底消除了人工逐个调整十六进制代码的繁重维护成本。

::: insight
色彩不是静止的像素，而是物理光波与人类神经中枢解码的复合产物。拥抱 OKLCH 和 APCA，标志着 Web 设计从“经验试错与肉眼比对”迈向了“参数化与可证明的知觉工程”。
:::

## 提取与迁移

- **在深浅色主题无缝转换中**：
  保持色相 $H$ 和彩度 $C$ 稳定，仅对感知明度 $L$ 执行对称翻转（如浅色背景 $L=95\%$，深色背景 $L=15\%$），生成的深色模式自然和谐，绝无传统反色的生硬感；
- **在数据可视化（Data Visualization）色板中**：
  构建连续型渐变色（Sequential Colormap）时，强制 $L$ 沿着数据大小单调递增，确保打印成纯黑白图表或严重色弱患者观察时，数据的相对大小关系依然清晰可辨。

## TL;DR

- 传统 HSL 的“明度 $L$”忽视了人类视网膜对不同波长的生理敏感度差异，仅改变色相就会导致实际感知明度和阅读对比度严重失真。
- 现代 OKLCH 空间实现了真正的知觉均匀：明度 $L$、彩度 $C$ 与色相 $H$ 正交独立，相同的 $L$ 绝对保障跨色相的一致视觉明度，并原生释放 Display P3 广色域性能。
- APCA 取代传统 WCAG 2.1 机械比值算法，将字号大小、字体粗细与明暗极性纳入动态神经感知计算，确立了科学可读性的新标杆。
