# 击键级模型

## 问题情境

在软件方案评审阶段，团队经常在多个功能原型之间举棋不定。例如，对于一个日常需要重复操作上百次的“查找并替换”功能：
- 方案 A：用户使用鼠标在主菜单中逐层点击 `编辑 → 查找与替换`，然后在弹窗中点击输入；
- 方案 B：用户直接敲击键盘快捷键 `⌘ + F`，键入内容后回车。

传统的评价方式是开发出完整的前端代码，招募数十名受试者在可用性实验室中进行秒表计时测试。然而，这种测试耗资巨大、开发周期漫长，且在需求设计初期完全无法提前介入。

工程师与人机交互学者需要一种能够在代码未写一行之前、仅凭原型设计图纸就能**定量推导熟练用户无差错任务耗时**的理论预测模型。

## 概念界定

::: definition [击键级模型（Keystroke-Level Model, KLM）]
由施乐帕洛阿尔托研究中心（Xerox PARC）的 Stuart Card、Thomas Moran 与 Allen Newell 于 1980 年提出，击键级模型是 GOMS 理论家族中最简明、最适宜工程落地的一种定量预测技术。
:::

KLM 将用户执行特定人机交互任务的过程严格拆解为一系列物理操作动作与认知准备操作，并赋予每个基本算子一个基于大量心理学生理实验标定的标准执行耗时，最终通过算子求和精确预测出熟练专家在**无差错（Error-Free Expert Performance）**情境下的基准任务时间：

$$
T_{\text{execute}} = \sum T_K + \sum T_P + \sum T_H + \sum T_D + \sum T_M + \sum T_R
$$

## 解释与依据

### 1. KLM 六大核心操作算子与经验参数

KLM 体系定义了四类物理算子、一类心理认知算子与一类系统响应算子：

| 算子符号 | 算子名称与定义 | 标准预估耗时（经验值） | 典型交互场景 |
| :--- | :--- | :--- | :--- |
| **$K$** | **击键（Keystroke / Button Press）**：敲击一次键盘按键或点击一次鼠标按键 | 约 **0.20 秒**（打字熟练者：0.08–0.28s，普通用户约 0.28s） | 敲击字母、回车键、空格键或鼠标左键单击 |
| **$P$** | **指向（Pointing）**：移动光标指向屏幕上的目标区域（遵循菲茨定律） | 约 **1.10 秒**（典型范围：0.8s 至 1.5s） | 握着鼠标将指针从文本移动到“保存”按钮 |
| **$H$** | **归位（Homing）**：双手在键盘与鼠标（或触摸板）之间的物理切换转移 | 约 **0.40 秒** | 手从键盘挪到鼠标握柄，或从鼠标放回键盘打字区 |
| **$D$** | **绘图（Drawing）**：使用指示设备绘制一组线段（较少用于常规界面） | 取决于矢量网格长度与线段数 | 自由手绘、拖拽画框 |
| **$M$** | **心理准备（Mental Preparation）**：用户做出下一步物理动作前的认知决策与检索 | 约 **1.35 秒**（典型范围：1.0s 至 1.5s） | 决定接下来要敲哪个键、在屏幕列表中定位目标项 |
| **$R$** | **系统响应（System Response）**：用户必须等待系统加载反馈的空闲时间 | 实际测量值（仅当大于用户认知准备时计入） | 等待后端 API 请求返回、等待文件保存完成 |

### 2. 认知心理算子 $M$ 的启发式放置规则

物理算子（$K, P, H$）由动作机械序列直接决定，而心理算子 $M$ 必须由评估者按照 Card-Moran-Newell 规则科学插入，避免随意高估或低估认知负担：

1. **初始默认插入**：在每个指向算子 $P$（移动鼠标定位目标）之前、在每次非连续键盘击键之前，默认插入一个 $M$；
2. **认知单元合并规则（Chunking）**：如果一串按键属于完全熟练的一个认知块（如输入一个熟悉的密码单词、敲击回车确认），在整串字符序列的第一个按键前保留一个 $M$，序列中间的所有 $M$ 必须剔除；
3. **预期重叠剔除**：如果下一次操作在当前动作进行中就已经被用户提前预测好（例如紧接着点击确认），后续的 $M$ 应被消除。

## 边界与辨析

### 1. KLM 的预测范围与局限性

- **适用场景**：
  - 预测熟练专家在日常机械任务中的极致效率；
  - 比较两套竞争交互原型（如命令行 CLI vs 表单 GUI）的相对效率差距；
- **不适用场景**：
  - **不考虑新手的学习与试错**：新用户在界面中迷失、阅读帮助说明的耗时不在 KLM 预测范围内；
  - **不考虑差错恢复（Error Recovery）**：KLM 严格假设用户不手滑、不输入错误（现实中犯错后的纠错耗时往往远超无差错基准时间）。

### 2. 案例对比推演：删除整段文本的效率竞争

假设任务是删除一个文档中的最后一行文字（由 20 个字符组成）：

- **策略一：长按 Backspace 退格键**：
  - 步骤：手已经在键盘上。用户停顿思考（$M$），随后连续敲击（或长按）退格键 20 次（$20 \times K$）。
  - $T_1 = M + 20 \times K = 1.35s + 20 \times 0.20s = 5.35 \text{ 秒}$。
- **策略二：鼠标双击选定整行后敲击 Delete**：
  - 步骤：手移向鼠标（$H$），思考并移动光标到行尾（$M + P$），双击鼠标选择（$2 \times K$），手放回键盘（$H$），敲击 Delete（$K$）。
  - $T_2 = H + M + P + 2K + H + K = 0.40s + 1.35s + 1.10s + 0.40s + 0.40s + 0.20s = 3.85 \text{ 秒}$。
- **策略三：键盘专业快捷键（Shift + Home 后敲 Delete）**：
  - 步骤：双手无需离键（无需 $H$）。思考组合键（$M$），敲击 Shift+Home（$2K$），敲击 Delete（$K$）。
  - $T_3 = M + 3K = 1.35s + 3 \times 0.20s = 1.95 \text{ 秒}$。

KLM 清晰揭示了策略三相比策略一实现了超过 2.7 倍的效率提升，直接指引了快捷键设计的巨大生产力价值。

::: insight
KLM 的核心工程启示在于：键盘与鼠标之间的物理归位算子（$H = 0.4s$）以及视线重新定位的心理算子（$M = 1.35s$）往往比按键本身的动作（$K = 0.2s$）贵得多。高效率界面应当减少键鼠频繁交替，保持输入流在单一设备上的连续性。
:::

## 提取与迁移

- **在现代命令行工具与快捷键设计中**：
  为高频终端命令设置短别名（如 `git st` 代替 `git status`），每次节省 4 个 $K$ 算子（近 1 秒），对每天敲击上百次命令的开发者具有显著的累积效益；
- **在金融交易终端（如彭博终端 Bloomberg Terminal）中**：
  交易员键盘采用定制专用实体功能按键，彻底剥除多级菜单和鼠标指向，将所有核心操作锁定在单次 $K$ 算子极限，保障数十亿美元高频交易的毫秒级执行。

## TL;DR

- 击键级模型（KLM）是一种能在界面开发前量化预测熟练专家无差错操作时间的理论工程工具。
- 交互动作被解构为 6 类基准算子：击键 $K$（0.2s）、鼠标指向 $P$（1.1s）、键鼠归位切换 $H$（0.4s）、心理认知准备 $M$（1.35s）以及系统响应等待 $R$。
- KLM 揭示了心理决策与键鼠交替的昂贵成本，指导工程师通过减少交互切换、提供连续键盘快捷键来最大化生产力。
