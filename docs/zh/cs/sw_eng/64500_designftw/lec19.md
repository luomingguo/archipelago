# Lec 19 色彩

## TL;DR

- 单色、类似色、互补色、分裂互补色和多色配色通过色相关系建立不同的协调与强调效果。
- 颜色应承担层级和状态提示，但文本可读性仍取决于足够的前景与背景对比度。
- 非典型色觉会改变颜色区分能力，因此重要信息不能只用色相编码，还需要文字、形状或位置冗余。

## 色彩设计范围

在人机交互与 Web 界面设计中，色彩绝非纯粹的审美装饰，而是一种高带宽的信息编码通道与物理工程约束。本讲系统剖析五个递进维度：

- **颜色如何工作（色彩物理与视觉生理学）**
- **不同的颜色空间与模型（从 sRGB、HSL 到现代知觉均匀空间 OKLCH）**
- **用颜色进行设计（经典色轮调和策略）**
- **可读性与无障碍计算（WCAG 相对对比度与新一代 APCA 模型）**
- **非典型色觉（色觉障碍适配与多通道冗余设计）**

## 颜色物理与视觉感知生理学

从物理本质而言，光是特定波长范围（约 380nm 至 750nm）的电磁辐射。人类视网膜并不直接测量全光谱，而是通过两类感光细胞将光子转化为神经电信号：

1. **视杆细胞（Rods）**：约 1.2 亿个，灵敏度极高，专司夜间弱光视觉（暗视觉），不分辨颜色；
2. **视锥细胞（Cones）**：约 600 万至 700 万个，专司明亮光线下的高分辨率彩色视觉（明视觉）。视锥细胞根据其光敏色素的吸收光谱峰值划分为三类：
   - **S 视锥（Short）**：峰值约为 420nm（蓝光）；
   - **M 视锥（Medium）**：峰值约为 530nm（绿光）；
   - **L 视锥（Long）**：峰值约为 560nm（黄绿光/红光）。

::: definition [对立色学说（Opponent Process Theory）]
神经生理学实验表明，视锥细胞的三色信号在视网膜神经节细胞和外侧膝状体中被重新编码为三对互相对立的神经通道：
- **明暗通道（Light-Dark / Achromatic）**：黑 vs 白；
- **红绿通道（Red-Green）**：红 vs 绿；
- **黄蓝通道（Yellow-Blue）**：黄 vs 蓝。
这一机制解释了为什么人类无法感知“带绿的红”或“带黄的蓝”，也决定了红绿盲往往成对发生。
:::

人眼视网膜对不同波长光线的能量感知灵敏度极不均匀（光度函数 Luminosity Function $V(\lambda)$）。人眼在 555nm（黄绿色）处灵敏度最高。这意味着：**相同辐射功率下，纯黄色看起来极为明亮，而纯蓝色看起来极为暗沉**。

## 现代颜色模型：从 sRGB、HSL 到 OKLCH 与广色域

### 传统模型的知觉陷阱：sRGB 与 HSL

早期计算机显示器基于阴极射线管（CRT）荧光粉发光特性建立了 **sRGB** 色彩空间，使用加色模型 `rgb(r, g, b)`。虽然计算机能精准控制红绿蓝发光强度，但数字空间上的线性变化并不等同于人类眼中的线性变化。

为了让人类更直观地选色，工程师在 1970 年代发明了 **HSL（色相、饱和度、亮度）**：
- $H$（Hue）：色相角度（0°–360°）；
- $S$（Saturation）：饱和度（0%–100%）；
- $L$（Lightness）：所谓“亮度”（0%–100%）。

::: pitfall [HSL 的感知不均匀陷阱]
HSL 最大的致命缺陷在于：**它的“Lightness”仅仅是数学上的几何变换，根本不代表人类感知的真实明度！**
例如：
- 纯黄：`hsl(60, 100%, 50%)`
- 纯蓝：`hsl(240, 100%, 50%)`
两者在 HSL 中的 $L$ 值完全相同（均为 50%）。然而在人类视觉中，纯黄的感知明度接近 90%，而纯蓝的感知明度仅有约 26%！
如果在设计系统中仅通过改变 HSL 的 $H$ 来生成主题强调色，文本与背景之间的可读对比度将瞬间崩溃。
:::

### 现代知觉均匀色彩空间：OKLCH

为彻底解决感知扭曲问题，国际照明委员会（CIE）先后推导出了 CIELAB、CIELCH，以及 2020 年由 Björn Ottosson 完善并被 W3C 纳入 CSS Color 4 / 5 标准的 **OKLCH**。

OKLCH 由三个感知正交的物理分量构成：
```css
/* 现代 CSS OKLCH 语法 */
color: oklch(0.7 0.15 140deg);
```
- **$L$（Perceived Lightness，感知明度）**：从 `0%`（完全黑）到 `100%`（纯白）。具有严格的知觉一致性——无论色相如何改变，相同的 $L$ 值在人类眼中始终保持完全相同的明亮度和阅读对比度！
- **$C$（Chroma，彩度）**：从 `0`（完全无彩灰度）到理论无上限（实际由显示屏色域边界决定，通常现代屏幕约 0.37）。数值与鲜艳度成物理感知线性比例。
- **$H$（Hue Angle，色相环）**：0° 至 360° 的色彩环（0° 为粉红，90° 为黄绿，140° 为翠绿，240° 为纯蓝）。

### 广色域（Wide Color Gamut）：Display P3

现代智能手机（如 iPhone、iPad、MacBook）与专业显示器普遍支持 **Display P3** 广色域，其色彩容积比老旧的 sRGB 大约 50%，能够呈现极度鲜活的高饱和霓虹绿、深邃红和鲜亮橙。

在现代 CSS 中，可以直接使用 `oklch()` 或 `color(display-p3 r g b)` 释放硬件全色域性能：

```css
:root {
  /* 在普通 sRGB 屏幕上安全回退，在 P3 广色域屏幕上呈现极限鲜艳色彩 */
  --brand-vivid: oklch(65% 0.28 145);
}

@supports (color: color(display-p3 1 1 1)) {
  .hero-glow {
    background: color(display-p3 0 1 0.2);
  }
}
```

## 用颜色进行设计

### 单色配色

使用同一种颜色的不同变化可以形成一种很有冲击力的配色方案，但如果不加入黑色、白色以及不同深浅的灰色来增强对比，就很难有效地使用这种配色。

应选择具有较大明暗变化（色调和阴影变化范围更广）的颜色，以提供足够的对比度。

![image-20260513130612206](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130612206.png)

### 类似色

在色轮上彼此相邻的颜色组合，会形成一种范围较窄但很和谐的配色方案。

与单色配色类似，类似色通常会带来偏暖或偏冷的整体感觉，具体取决于它们在色轮中的位置。

![image-20260513130635540](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130635540.png)

### 互补色

位于色轮相对两端的颜色提供了最强的对比效果。

如果能够克制增加更多颜色的冲动，只使用两种互补色，可以创造出非常强烈甚至令人震撼的视觉效果。

但需要合理搭配，否则它们可能会产生冲突感。

![image-20260513130655226](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130655226.png)

### 分裂互补色

这种互补配色的变体是：选取一个主色，再选取它互补色两侧的两个颜色。

这些颜色具有较高的视觉对比，但相比纯互补色，视觉张力更弱、更柔和

![image-20260513130734827](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130734827.png)

### 三色配色

在色轮上等距离分布的三种颜色组合，可以产生强烈且生动的视觉效果。

有些配色会显得大胆，有些则更精致、克制。

你也可以对这种方法进行调整，例如用其中一种颜色的浅色或深色来替代纯色，从而降低整体冲突感。

![image-20260513130747967](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130747967.png)

### 四方配色

这种配色方案因为既有强对比又能保持一定和谐感，所以很受欢迎。它由两组互补色构成。

但如果四种颜色使用比例相同，会很难协调。

因此通常需要选择一种主色作为设计的主导色，其余颜色作为辅助色来支持整体视觉效果。

![image-20260513130756034](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/image-20260513130756034.png)

可以使用工具来评估 [adobe color](https://color.adobe.com/create/color-wheel)

一个建议： **可以从照片上拾取颜色**。

## 可读性与颜色计算

在 Web 交互中，色彩的第一个硬性工程约束是**可读性（Legibility）**。如果读者无法看清文字，任何美学考量都毫无意义。在线对比度验证可参考 MIT 课程与 W3C 推荐的工具：[apps.colorjs.io/contrast](https://apps.colorjs.io/contrast)。

### 1. WCAG 2.1 相对亮度对比度算法

Web 内容无障碍指南（WCAG 2.1）将文本与背景的对比度定义为相对亮度（Relative Luminance $L$）的比值：

$$
\text{Contrast Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05} \quad (L_1 > L_2)
$$

其中 $L_1$ 为较亮颜色的相对明度，$L_2$ 为较暗颜色，常数 $0.05$ 模拟了环境环境光散射（Flare）。该公式产生介于 $1:1$（完全无对比）到 $21:1$（纯黑纯白）之间的无量纲数值。

**WCAG 2.1 合规底线**：
- **普通正文文本**（小于 18pt 或小于 14pt 粗体）：至少 **4.5:1**（AA 级），推荐 **7:1**（AAA 级）；
- **大号文本**（大于等于 18pt 或大于等于 14pt 粗体）：至少 **3:1**（AA 级）；
- **UI 控件与关键图形要素**（如输入框边框、选中焦点圈）：至少 **3:1**。

### 2. 现代 APCA（高级知觉对比度算法）与局限突破

WCAG 2.1 的数学公式虽然简单，但存在严重的知觉缺陷：
1. **未考虑空间频率与字重**：相同的颜色对比在 12px 超细体（难以辨认）与 32px 粗体（清晰可见）上的感知完全不同，旧公式却一视同仁；
2. **极性倒错假象**：人眼晶状体在暗色背景下看亮色文本时会发生光晕衍射（Halation），但 WCAG 2.1 对黑底白字与白底黑字给出了完全相同的评分。

为了克服这些局限，正在制定的 WCAG 3 规范引入了 **APCA（Advanced Perceptual Contrast Algorithm）**。APCA 基于神经生理学与人眼空间对比度传递函数（CSF），计算感知明度对比值 $L^c$（范围约 -108 到 +106），并直接关联具体字号和字重。

### 提高可读性对比度的工程实践

- **利用 OKLCH 调节感知明度**：相应地提高或降低其中一种颜色的 $L$ 属性，保持视觉一致；
- **增大字号与字体粗细（Font Weight）**：大字重与大字号能显著降低人眼辨识所需的极限对比度；
- **运用文字阴影（`text-shadow`）**：在复杂或多变图像背景上渲染文本时，利用软阴影建立微边界；
- **添加半透明暗色/浅色遮罩层（Scrim / Backdrop Overlay）**：在文字后方叠加 `background: rgb(0 0 0 / 0.5)`。

这些方法的目标都是：让文字与背景之间在各种环境光线（如强日光、暗室夜览）下均清晰可辨。

### 非典型色觉

下面列出的是不同类型色觉异常的大致人群比例：

| 类型                                   | 男性 XY | 女性 XX |
| -------------------------------------- | ------- | ------- |
| Protanopia（红色盲）                   | 1.0%    | 0.02%   |
| Deuteranopia（绿色盲）                 | 1.1%    | 0.01%   |
| Tritanopia（蓝色盲）                   | 0.002%  | 0.001%  |
| Cone monochromatism（视锥单色视觉）    | 0.0%    | 0.0%    |
| Rod monochromatism（杆状细胞单色视觉） | 0.003%  | 0.002%  |
| Protanomaly（红色弱）                  | 1.0%    | 0.02%   |
| Deuteranomaly（绿色弱）                | 4.9%    | 0.38%   |
| Tritanomaly（蓝色弱）                  | 0.0%    | 0.0%    |
| 总计                                   | 8.0%    | 0.4%    |

对 UI 设计意味着，不要只靠颜色传达信息。 例如不要 红色 = 错误； 绿色  = 正确。 建议加上图表和颜色， 因为部分用户可能根本分不清。

优秀设计通常会：

- 同时使用颜色 + 图标
- 使用足够亮度对比
- 避免红绿直接对抗
- 提高文字可辨认性

::: insight
色彩系统首先是信息编码系统，其次才是装饰系统。为状态同时提供颜色与非颜色线索，既改善可访问性，也能应对低质量屏幕、强光和品牌主题变化。
:::
