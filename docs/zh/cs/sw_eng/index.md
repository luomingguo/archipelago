# 编程与软件工程

## TL;DR

- 编程基础、软件构造与软件设计分别解决程序如何执行、模块如何保持正确、功能如何满足需求的问题；学习时应把运行机制、行为规格与设计目的联系起来。
- Shell、Git、调试、测试与自动化交付贯穿各阶段，适合与编程课程同步练习，在真实项目中形成可重复的工作流。
- Web 交互、性能工程、多核编程与算法工程是不同的深入方向；按当前问题选择分支，并补齐相应的数学、算法与系统基础，无须依次修完所有课程。

### 软件设计与用户交互

| 课程 | 核心问题与内容 |
| --- | --- |
| [6.1040 软件设计](./61040_software_design/index.md) | 如何把需求转化为清晰的功能模型？通过概念的目的、状态、动作及同步关系组织系统行为。 |
| [6.4500 Web 设计：语言和用户接口](./64500_designftw/index.md) | 如何实现易学、有效且有反馈的交互？结合 HTML、CSS、JavaScript 与用户测试研究 Web 界面。 |

6.1040 侧重功能与行为的概念结构，6.4500 侧重用户界面与交互实现。两者可以围绕同一个项目互相检验：界面是否准确表达系统状态，系统模型是否支持用户要完成的任务。

### 性能、并发与算法工程

| 课程 | 核心问题与内容 |
| --- | --- |
| [6.1060 软件性能工程](./61060_software_performance_engineer/index.md) | 时间花在哪里，优化是否有效？围绕性能测量、缓存局部性、编译器、向量化与并行执行分析实现成本。 |
| [6.5080 多核编程](./65080_multicore_programming/index.md) | 多线程如何同时保证正确性与扩展性？研究同步、并发数据结构、内存回收与工作分配。 |
| [6.5060 算法工程](./65060_algorithm_engineer/index.md) | 算法在真实机器上的代价是什么？结合并行、缓存与外存模型，比较理论分析和实现测量。 |

进入这一分支前，应检查自己的算法、内存模型和系统基础。多核编程不必排在性能工程之后；当问题集中在线程安全与同步协议时，可以直接以多核课程为主线，并按需补充性能分析。

### 贯穿各阶段的工程工具链

[6.NULL 现代软件工程工具链与开发者素养](./6NULL_engineering_toolchain/index.md)覆盖 Shell、开发环境、调试、Git、代码打包、智能体编程、协作与代码质量。建议边学边用：用 Git 记录实验，用测试固定预期，用调试与性能工具解释结果，再把构建和检查变成可重复的命令。

## 我的理解

::: insight 用同一个项目连接不同课程的判断标准
学习这些课程时，我更倾向于反复改进同一个小项目：先用编程基础解释执行过程，用规格和测试明确正确行为，再用概念设计审视功能边界，最后根据测量结果优化性能。这样每次修改都需要回答具体问题：它改变了什么行为，保留了什么约束，证据是否足以支持收益？工具链让这些判断可以重现，而不同课程提供各自的分析尺度。能在尺度之间切换，比单纯积累框架和命令更有迁移价值。
:::
