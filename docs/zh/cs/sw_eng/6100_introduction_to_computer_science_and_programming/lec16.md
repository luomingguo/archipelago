# Lec 16 组合最优化与决策树模型（Optimization & Decision Trees）

> MIT 6.100 · 计算机科学与 Python 编程导论 · Fall 2026 · 教材参考：Guttag 6, 14.1

## TL;DR

- **组合最优化问题（Combinatorial Optimization）**：在有限离散的候选状态空间中寻找使得目标收益最大（或成本最小）且满足全部约束条件的最优子集。
- **贪心启发式算法的局限**：按单价、总价值或最小重量排序的局部贪心策略算法速度极快（$O(N\log N)$），但由于缺乏全局视野，极易错失全局最优解。
- **0/1 决策树穷举模型**：对每个候选物品做出“选（1）”或“不选（0）”的二元抉择，形成高度为 $N$、叶子数为 $2^N$ 的二叉状态树，为精确求解提供基础模型。

## 1. 经典组合优化：背包问题（Knapsack Problem）

现实工程决策往往受制于严格的物理资源预算（如数据中心功耗上限、卡车载重上限、投资组合总资金）。

最经典的离散组合优化模型是**0/1 背包问题（0/1 Knapsack Problem）**：
- 设有 $N$ 件候选物品，每件物品具有价值 $v_i > 0$ 和重量 $w_i > 0$；
- 背包具有最大承重上限 $W$；
- 目标：选取一个物品子集 $S \subseteq \{1, \dots, N\}$，在总重量不超过约束的前提下，使得总价值最大化：
  $$\max \sum_{i \in S} v_i \quad \text{s.t.} \quad \sum_{i \in S} w_i \le W$$

“0/1”的含义是：每件物品要么完整装入背包（1），要么完全不装入（0），不允许将物品切割为任意分数。

## 2. 贪心启发式算法及其失效陷阱

面对组合优化，工程上最直观的本能策略是**贪心启发式（Greedy Heuristics）**。贪心算法的基本逻辑是在每一步决策时，都仅仅依据某种局部度量指标做出当前看似最合算的选择，并且一旦做出决定便绝不反悔回溯。

根据不同的业务直觉，我们可以设计出三种典型的贪心规则：
1. **最高价值优先（Greedy by Value）**：优先挑选单价最昂贵的物品，直觉认为价值越大的物品对总收益贡献越高；
2. **最轻重量优先（Greedy by Weight）**：优先挑选占用空间最轻巧的物品，直觉认为体积越小越能腾出空间容纳更多物品；
3. **单位密度优先（Greedy by Density）**：优先挑选性价比 $\frac{v_i}{w_i}$ 最高的物品，试图实现单位重量资源利用效率的最大化。

为了以参数化方式横向对比这三种策略，我们封装一个通用的贪心选择框架。该框架接收一个排序键函数 `key_fn`，在一次降序排序后，线性贪心地装载背包直到超重：

```python
class Item:
    def __init__(self, name: str, value: float, weight: float):
        self.name = name
        self.value = value
        self.weight = weight
        
    def density(self) -> float:
        return self.value / self.weight
        
    def __repr__(self) -> str:
        return f"{self.name}(v={self.value}, w={self.weight})"

def greedy_knapsack(items: list, max_weight: float, key_fn) -> tuple:
    """
    根据特定 key_fn 排序规则执行贪心选择
    """
    # 按贪心指标从大到小降序排列
    sorted_items = sorted(items, key=key_fn, reverse=True)
    result = []
    total_val, total_wt = 0.0, 0.0
    
    for item in sorted_items:
        if total_wt + item.weight <= max_weight:
            result.append(item)
            total_wt += item.weight
            total_val += item.value
            
    return total_val, result
```

下面我们构造一个精心设计的物品集合。在这组数据中，物品在价值和重量上呈现出强烈的非对称性，能够直接揭示出所有局部贪心策略的全面溃败：

```python
items_pool = [
    Item("钟表", 175, 10),
    Item("名画", 90, 9),
    Item("收音机", 20, 4),
    Item("书籍", 50, 2)
]
max_limit = 20

# 策略 1：按性价比贪心
val_density, chosen_density = greedy_knapsack(items_pool, max_limit, lambda x: x.density())
print(f"按性价比贪心价值: {val_density} | 选中的物品: {chosen_density}")
```

在最大承重为 20 的约束下，贪心算法的推演暴露了致命缺陷：
- 性价比贪心首先选中书籍（密度 25.0）和钟表（密度 17.5），消耗重量 12，总价值 225；然而此时剩余承重仅剩 8，无法再装入名画（重 9），最终只能停留在 225。
- 价值贪心会首先挑走钟表（价值 175，重 10），随后装入书籍（价值 50，重 2），得到完全相同的次优解 225。
- 然而全局最优解其实是抛弃性价比极高的钟表，同时选择“名画 + 书籍 + 收音机”，总重量恰好为 $9 + 2 + 4 = 15 \le 20$，总价值高达 $90 + 50 + 20 = 160$；更优组合是选择“钟表 + 名画”，总重量 $10 + 9 = 19 \le 20$，总价值更是高达 **265**！

贪心算法的目光短浅，导致其极易为了吞下局部的微小诱饵而浪费宝贵的背包剩余容量，在 0/1 背包这种离散不可分割的硬约束场景下，贪心算法无法提供全局最优的数学保证。

## 3. 0/1 决策树穷举模型

为了确保万无一失地捕获全局最优解，算法必须具备审视全部可行组合的能力。

0/1 决策树将决策过程组织为一个二叉树结构：
- **树的深度**：对应候选物品的序列编号 $0, 1, \dots, N-1$；
- **左子树（选取分支）**：将当前物品纳入解集，背包可用容量扣减 $w_i$；
- **右子树（放弃分支）**：将当前物品弃置不选，背包可用容量保持不变。

```text
               根节点: 决策物品 0 (钟表)
             /                           \
       [选 钟表]                       [不选 钟表]
       剩余容量: 10                     剩余容量: 20
      /            \                  /            \
  [选 名画]     [不选 名画]       [选 名画]      [不选 名画]
(超重! 剪枝)     继续决策...     剩余容量: 11     继续决策...
```

对于包含 $N$ 件物品的集合，决策树的叶子节点总数为 $2^N$。当 $N = 10$ 时，$2^{10} = 1024$ 瞬间可解；但当 $N = 50$ 时，$2^{50} \approx 10^{15}$，即使全球最快的超级计算机也无法在有生之年穷举完毕。

这种组合空间爆炸驱使我们在后续两讲中探索**状态剪枝**与**动态规划**这两把开山利刃。

::: pitfall 忽视离散与连续背包的本质差异
若物品是可任意分割的液体或金砂（分数背包，Fractional Knapsack），按照性价比降序选择的贪心算法在数学上严格证明能达到 100% 全局最优。许多初学者将分数背包与 0/1 背包混淆，误以为贪心策略在离散背包中也是精确解。
:::

## 我的理解

::: insight 从局部启发到全局状态树的认知跃迁
贪心算法教会我们如何以最少的时间博取次优收益，而决策树模型则为我们建立了通往全局真理的完整地图。尽管 $2^N$ 的指数之墙令人望而生畏，但只有把问题严密形式化为二叉决策树，我们才能清晰看到搜索空间中的每一处对称与冗余，从而为后续的记忆化重叠子问题合并（动态规划）铺平道路。
:::
