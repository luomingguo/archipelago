# Lec 15 匿名函数、推导式与函数式编程范式（Lambda & Comprehensions）

> MIT 6.100 · 计算机科学与 Python 编程导论 · Fall 2026 · 教材参考：Guttag 4.4, 5.3.2, 5.8

## TL;DR

- **匿名单行函数（Lambda）**：`lambda args: expr` 允许在表达式上下文中即时构造无需命名的轻量函数对象，常作为排序键或高阶函数的即抛参数。
- **推导式（Comprehensions）与声明式构建**：列表、字典与集合推导式将“循环遍历 + 过滤筛选 + 映射转换”高度提炼为单行声明式表达式，兼具可读性与 C 底层循环字节码加速。
- **生成器表达式与惰性求值**：圆括号包裹的生成器表达式仅在迭代消费时按需逐个计算产出数据，以 $O(1)$ 的恒定内存开销流式处理超大规模数据集。

## 1. Lambda 表达式：匿名函数的构造与应用场景

在传统的 Python 函数定义中，我们使用 `def` 关键字在当前命名空间中绑定一个显式名称。然而在许多实际开发场景中，我们只需要一个生命周期仅存在于某一瞬时的临时微型函数（例如排序准则或临时条件过滤）。

为了消除定义大量单行函数的命名负担，Python 引入了源自阿隆佐·邱奇 $\lambda$ 演算的 **Lambda 表达式（Lambda Form）**：

```python
# 语法结构：lambda 参数列表: 单一返回表达式
square = lambda x: x ** 2
print(square(5))  # 25
```

::: definition Lambda 表达式的语法约束
1. **纯单行表达式**：Lambda 主体只能包含一个单一的计算表达式，严禁包含 `return`、`if-else` 多行控制块、`while` 循环或赋值语句。
2. **自动返回求值结果**：表达式的计算结果隐式作为整个函数的返回值。
:::

### 典型工业应用：复杂多维数据的即时排序

在处理复合数据结构时，排序规则往往不是简单的单一数值比较，而是涉及到多维字段的组合权衡。在调用列表的 `sort()` 原地排序方法或内置高阶函数 `sorted()` 时，`key` 参数接收一个单参数投影函数，该函数接收序列中的每一个原始元素，并返回一个用于比较大小的代理标量或元组。

这正是 Lambda 表达式最能大放异彩的典型场景。考虑以下包含学生多元信息的元组列表，我们需要实现“首要优先按学业绩点降序排布，若绩点完全相同则按年龄升序排列”的双重比较规则：

```python
# 候选学生列表：(姓名, GPA, 年龄)
students = [
    ("Alice", 3.85, 20),
    ("Bob", 3.92, 19),
    ("Charlie", 3.85, 22)
]

# 复合多级排序：利用元组的按位比较特性，对数值取负实现逆向降序
students_sorted = sorted(students, key=lambda s: (-s[1], s[2]))
print(students_sorted)
# 输出: [('Bob', 3.92, 19), ('Alice', 3.85, 20), ('Charlie', 3.85, 22)]
```

在上述代码中，Python 的元组比较协议首先对比元组的第一项 `-s[1]`（由于取了负号，原本更高的 GPA 在数值上变得更小，从而排在前面）；当第一项持平时，算法无缝回退到第二项 `s[2]` 进行标准的自然升序比较。相比于在外部单独定义一个仅使用一次的显式辅助函数，内联的 Lambda 表达式极大地收敛了代码的上下文分散度。

## 2. 容器推导式（Comprehensions）

推导式是 Python 最具表现力的语法糖之一。它将传统的初始化空容器、编写 `for` 循环追加元素以及 `if` 条件过滤这三步繁琐流程，压缩为清晰的声明式数学集合表示法：
$$\{f(x) \mid x \in S \land P(x)\}$$

### 列表推导式（List Comprehension）

```python
# 传统命令式写法：
squares_even = []
for x in range(10):
    if x % 2 == 0:
        squares_even.append(x ** 2)

# Pythonic 声明式推导式：
squares_even = [x ** 2 for x in range(10) if x % 2 == 0]
# 结果: [0, 4, 16, 36, 64]
```

### 字典与集合推导式（Dict & Set Comprehensions）

推导式不仅适用于线性列表，还完美覆盖了哈希集合与键值字典的构造。其语法与列表推导式高度同构，仅需将外部的外壳符号替换为花括号 `{}` 即可。

在集合推导式中，表达式直接生成无重复的独立元素集合；而在字典推导式中，循环体头部采用 `key_expr: value_expr` 的冒号键值对形式，实现从原始序列向全新关联映射关系的快速变形：

```python
words = ["apple", "banana", "cherry", "avocado"]

# 集合推导式：提取所有单词的首字母集合（底层自动完成哈希去重）
initials = {w[0] for w in words}  # {'a', 'b', 'c'}

# 字典推导式：建立单词到其长度的映射表，并仅保留长单词
word_len_map = {w: len(w) for w in words if len(w) > 5}
# {'banana': 6, 'cherry': 6, 'avocado': 7}
```

值得深入强调的是，推导式不仅仅是代码外观上的简化。在 CPython 虚拟机的字节码实现层面，推导式直接映射为经过深度特化的底层 C 循环指令（如专门用于高速追加的 `LIST_APPEND` 与 `MAP_ADD`），消除了在 Python 字节码层反复解析 `.append()` 属性查找的额外开销，因此运行性能通常比手动显式调用的 `for` 循环快 20%~30%。

## 3. 生成器表达式与惰性求值（Lazy Evaluation）

如果将列表推导式的方括号 `[]` 替换为圆括号 `()`，Python 并不会生成一个“元组推导式”，而是产生一个具有划时代意义的对象——**生成器表达式（Generator Expression）**。

列表推导式遵循**立即求值（Eager Evaluation）**策略：它会立刻在堆内存中把所有计算结果全部物化（Materialize）出来。如果目标数据量达到一亿个元素，程序将瞬间耗尽数个吉字节（GB）的物理内存而崩溃：

```python
# 立即求值：瞬间开辟大块内存
huge_list = [x ** 2 for x in range(10000000)]  # 占用数百兆内存
```

而生成器表达式遵循**惰性求值（Lazy Evaluation）**协议：它在初始创建时仅占用几十个字节的极小固定栈帧，只在下游迭代器调用 `next()` 时，才实时计算并产出下一个值：

```python
# 惰性求值：内存占用仅约 100 字节的生成器迭代器
huge_gen = (x ** 2 for x in range(10000000))

# 消费生成器：求和过程中无需一次性存储所有平方数
sum_of_squares = sum(x ** 2 for x in range(1000000))
print(f"前一百万个平方和：{sum_of_squares}")
```

::: pitfall 滥用深层嵌套推导式破坏可读性
推导式支持多层嵌套循环（如矩阵扁平化 `[item for row in matrix for item in row]`）。然而，一旦推导式跨越了 2 个以上的循环或伴随复杂的条件分支，代码将变得极其晦涩。良好的工程准则是：“当单行推导式超过一行编辑器视口宽度时，应当重构回标准的显式循环或抽离独立辅助函数”。
:::

## 我的理解

::: insight 声明式代码与意图优先
从命令式循环到推导式与高阶函数，体现了编程语言从“指示计算机如何逐步搬移数据（How）”向“声明我们期望得到什么样的数据特征（What）”的高级演进。推导式消除了机械的状态维护变量，让代码意图跃然纸上。在数据科学与系统构建中，善用惰性生成器更是构建高吞吐低内存管道的绝对利器。
:::
