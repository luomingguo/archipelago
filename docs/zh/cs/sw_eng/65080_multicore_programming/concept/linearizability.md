# 线性一致性（Linearizability）

## 问题情境

在多核多处理器与分布式系统中，多个并发线程可能在时间轴上重叠调用同一个共享对象的方法（例如两个线程并发向队列压入数据）。在单线程顺序计算中，对象的行为完全由前置条件与后置条件的顺序规范界定；但在并发执行下，方法调用不再是瞬时的单点，而是跨越一段物理时间的区间（由调用事件与响应事件构成）。当并发操作的区间在时间轴上相互交错时，我们如何从数学和工程上严格定义该并发执行是否是“正确”的？

## 概念界定

::: definition 线性一致性（Linearizability）
由 Maurice Herlihy 和 Jeannette Wing 于 1990 年提出的一种强一致性正确性条件。一个并发系统的执行历史满足线性一致性，当且仅当系统中的每个方法调用都可以在其调用事件（Invocation）与响应事件（Response）之间的某个离散物理时间点——**生效点（Linearization Point）**上原子瞬时生效，使得所有操作在按其生效点排序后，完全满足该对象单线程顺序规范，并严格保留操作之间的全局真实物理时间先后序。
:::

## 解释与依据

线性一致性的理论大厦建立在两大支柱之上：

1. **瞬时原子生效点（Linearization Point）**：
   并发方法的执行可能涉及数十条机器指令，但在该区间内部，必定存在一个关键的原子步骤（例如一条原子 CAS 指令成功修改了指针、或者持有了互斥锁的瞬间），使得该操作对外部世界的状态突变一次性不可逆地完成。这个瞬时时刻即为生效点。将所有操作按照它们各自的生效点在全局时间轴上投影，便得到一条严格等价的等效顺序执行历史。
2. **可组合性定理（Composability / Locality Theorem）**：
   线性一致性最卓越的性质在于其**局部性（Locality）**。数学定理证明：一个并发系统满足线性一致性，当且仅当系统中的每一个独立组件对象都满足线性一致性。
   $$H \text{ is linearizable} \iff \forall x \in \text{Objects}, \quad H|x \text{ is linearizable}$$
   这一性质彻底解决了并发软件工程中的模块化危机：工程师可以独立开发并证明一个并发栈与一个并发队列的正确性，而后放心地将它们拼接组合，无需担心由于模块组合而诱发出全局一致性破裂。

::: insight 线性一致性作为物理时间与形式抽象的桥梁
线性一致性的伟大之处在于它既尊重“真实物理时间的因果律”，又保留了“纯粹顺序代码的直观抽象”。如果操作 A 在物理时间上先于操作 B 开始之前就已经彻底返回，那么在等效顺序历史中 A 绝不可能排在 B 之后。它在多核异步重叠的混沌执行中划定了一条唯一确定的实时因果链，成为了现代并发数据结构（乃至分布式系统中的 Raft / Spanner）最为公认的黄金标准。
:::

## 边界与辨析

- **与顺序一致性（Sequential Consistency, SC）的辨析**：
  - *相同点*：两者都要求并发操作在逻辑上映射为某种符合顺序规范的全序序列，且单个线程内部必须满足程序代码序（Program Order）。
  - *核心差异一（物理时间约束）*：顺序一致性不强制保留真实物理时间的先后序（只要重排后各线程感觉良好即可）；而线性一致性强约束“若 A 在 B 开始前已返回，则 A 必须排在 B 前”。
  - *核心差异二（可组合性）*：线性一致性具备局部性与强可组合性；而顺序一致性**不可组合**（两个各自顺序一致的对象组合后的系统可能违背顺序一致性）。
- **与静止一致性（Quiescent Consistency）的辨析**：
  静止一致性仅在系统没有任何并发操作的“静止期”之间保留先后序，而在活动期内部允许操作任意乱序，因此约束更弱、吞吐更高。
- **代价与边界**：
  为了提供严格的线性一致性保证，硬件和算法往往必须付出内存屏障（Memory Barrier）或原子指令的通信开销。在某些不要求绝对强一致的高通量统计场景中，弱一致性模型可能具备更高的性能扩展潜力。

## 提取与迁移

- **主动唤醒思考题**：
  1. *为什么说在基于互斥锁保护的方法调用中，该方法的生效点（Linearization Point）通常位于释放锁或关键写入的瞬间？*
     - **参考答案**：因为在持有独占锁期间，其他线程无法观测或修改共享状态。在临界区内完成核心数据更新并释放锁的瞬间，该操作的修改才正式暴露给并发世界，在此点之前操作尚未暴露，在此点之后其他线程必然观测到其新状态，符合瞬时生效的定义。
  2. *在无锁算法（如基于 CAS 的 Treiber 栈）中，`push()` 操作的生效点位于哪一行代码？*
     - **参考答案**：位于底层 `AtomicReference.compareAndSet(oldHead, newHead)` 指令执行成功的瞬间。CAS 失败的重试循环不构成生效点；一旦 CAS 硬件指令原子成功，新节点瞬间被立为新栈顶，成为不可逆的事实。

## TL;DR

- 线性一致性要求每个并发方法调用在其时间区间内的某个瞬时生效点上原子生效，满足对象的单线程顺序规范。
- 强制保留全局真实物理时间的先后顺序：若操作 A 在操作 B 开始前已返回，则 A 必排在 B 之前。
- 具备局部性（Locality）与可组合性（Composability），是现代多核无锁数据结构与强一致分布式系统的核心判定准则。
