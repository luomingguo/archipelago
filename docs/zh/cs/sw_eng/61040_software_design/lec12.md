# Lec 12 接触用户：问题与设计（Engaging Users: Problem & Design）

本讲聚焦软件设计早期的**形成性用户接触**（*Formative User Engagement*）：如何跳出孤芳自赏的设计者思维，在代码定型之前与真实用户和利益相关者协同，验证问题框架与概念草图。

## TL;DR

- 用户接触不是产品完工后的验收考试，而是在问题发现与交互草图阶段就介入的共同探索（Co-design）。
- 形成性评估（*Formative*）旨在发现“用户在想什么、遇到了什么困惑”，而总结性评估（*Summative*）仅测量任务完成度与速度。
- 采用认知走查（*Cognitive Walkthrough*）检验概念心智模型：用户能否看出正确意图、能否识别动作入口、能否理解系统反馈。
- 绝不向用户兜售解决方案或询问他们“想要什么”，而要深度挖掘他们当前的实际工作绕行方式与真实摩擦。

## 形成性接触的核心方法

### 1. 探寻替代方案（Workarounds）与实际摩擦

用户很少能直接清晰地描述自己的软件需求，但他们身上总能观察到为了应对现有系统不足而产生的“绕行方案”（*Workarounds*，如用 Excel 共享表格管理复杂任务，或在纸上记录关键编号）。这些绕行方案正是新概念诞生的金矿。

### 2. 认知走查（Cognitive Walkthrough）四问

在概念草图或低保真线框图上，设计者必须带真实用户演练核心旅程，并在每一步追问：

1. **意图形成**：用户是否清楚在当前界面下自己需要达成什么目标？
2. **动作可见**：满足该目标的动作入口（按钮、链接、表单）对用户而言是否可见、显眼？
3. **关联理解**：用户是否能将可见动作与他们心中的目标正确关联起来（Affordance）？
4. **反馈评估**：动作执行后，系统给出的状态变化反馈是否让用户清楚自己正在接近目标？

### 3. 防范“验证者陷阱”（Confirmation Bias）

设计者在测试自己设计的原型时，往往会下意识地：
- 替用户解释按钮的作用；
- 引导甚至诱导用户点击特定区域；
- 将用户的迷茫归咎于“这个人不是典型目标群体”。

正向的做法是**保持沉默、忠实记录**，把每一次用户的误解视为系统暴露出的概念设计缺陷。

::: insight
用户测试的本质不是评估用户聪不聪明，而是以用户为探针，测量你的概念模型与真实人类心理模型之间的“语义位移”。如果你必须在旁边用语言指导用户才能让他们完成流程，说明你的设计在概念层就已经破产了——因为软件发布后，你无法坐在每个用户的电脑旁替他们解释。
:::
