# Lec 6 共享内存图处理与 Ligra 框架（Shared-Memory Graph Processing & Ligra）

## TL;DR

- **Ligra 的双原语抽象**：将极其复杂的并行图遍历逻辑凝练为两个极简的通用算子——`vertexMap`（顶点集映射）与 `edgeMap`（边集条件过滤与状态转移），为多核图算法提供了统一的表达模型。
- **Direction-Optimizing 的双向遍历突破**：Scott Beamer 提出的双向优化 BFS 彻底颠覆了传统的由前沿向外单向扩展模式；在密集前沿阶段动态切换为从未访问节点反向拉取（Pull），避开了高冲突的原子写入。
- **自适应阈值与细粒度负载均衡**：Ligra 根据当前活跃前沿的出边总数与未遍历边数的动态比例，自适应在稀疏 Push 模式与密集 Pull 模式间无缝切换，在单机多核上以数行代码击溃大规模分布式图框架。

## 传统并行图计算的体系结构瓶颈

图算法（如 BFS、PageRank、连通分量、单源最短路）在现代计算系统中具有极高的应用价值，但它们也是对计算机硬件体系结构最为严苛的“反模式”杀手：
1. **数据访问极度无序（Random Access）**：真实世界图（如社交网络、网页链接、知识图谱）具有无标度（Scale-Free）特性，节点度数呈幂律分布。遍历图时，内存指针跳转完全不规则，导致 L1/L2/LLC 缓存缺失率极高，访存模式呈现彻底的随机离散读写。
2. **极低的计算密度（Low Compute-to-Memory Ratio）**：边访问通常仅伴随一次简单的距离比较或权重累加，整机的运行效率完全被内存总线延迟与带宽扼杀。
3. **并发写入的严重锁竞争（Atomic Contention）**：当多个线程同时试图遍历同一个超级节点（Hub Node，度数高达数十万甚至数千万）时，对目标顶点状态的并行原子操作（如 `compare_and_swap`）将导致严重的缓存行反弹（Cache Bouncing）与总线仲裁阻塞。

## Ligra 框架的设计哲学

2013 年，Julian Shun 与 Guy E. Blelloch 在 PPoPP 会议上提出了轻量级共享内存图计算框架 **Ligra**。

Ligra 的核心设计洞见是：**通过统一的数据类型与通用的映射原语，将图拓扑的并行调度优化与上层算法的业务逻辑完全解耦**。

### 两大核心数据抽象

1. **Graph**：采用高效的压缩稀疏行（Compressed Sparse Row, CSR）格式，同时保存原图的正向出边数组与反向入边数组，支持常数时间寻址任意节点的邻居列表。
2. **`vertexSubset`**：表示当前正在参与计算的活跃顶点子集。Ligra 在底层自适应选择两种内部物理编码：
   - **稀疏表示（Sparse Array）**：当活跃顶点较少时，直接存储无序的顶点 ID 整数数组。
   - **密集表示（Dense Bit-Vector）**：当活跃顶点占比较大时，采用每个节点占 1 个比特的紧凑位图表示，将内存占用压缩至极致。

### 核心映射算子：`edgeMap`

`edgeMap` 是 Ligra 的核心驱动引擎。它接受一个当前活跃的顶点集 $U$、一个边处理函数 $F(u, v)$，以及一个条件过滤器 $C(v)$，返回产生更新的新活跃顶点子集：
$$
\text{Out} = \text{edgeMap}(G, U, F, C)
$$
其形式化语义为：遍历所有从 $u \in U$ 出发指向满足 $C(v) == \text{True}$ 的邻居节点 $v$ 的有向边 $(u, v)$。若边函数 $F(u, v)$ 判定成功，则将目标节点 $v$ 加入输出集合 $\text{Out}$。

## Direction-Optimizing 机制（Push 与 Pull 的动态转换）

在传统的图遍历（如 BFS）中，算法从源点开始逐层向前推进。这一过程是**由前沿主动向外推送（Push / Top-Down）**：每个在前沿集合中的节点 $u$，主动检查其所有邻居 $v$；若 $v$ 未被访问，则通过原子的 CAS 操作将 $v$ 标记为已访问，并将其推入下一轮前沿。

```text
Push (Top-Down):   (前沿 u) ───[原子 CAS 竞争]───> (未访问 v)
                     多对一冲突严重，需要原子指令与总线锁

Pull (Bottom-Up):  (未访问 v) <───[无锁只读探测]─── (前沿 u)
                     一对多拉取，一旦命中立即停止，零写入冲突
```

### 为什么在图中心阶段 Push 会崩溃？

在真实世界的幂律网络中，遍历一旦触及几个核心枢纽，前沿规模将在几步之内指数级膨胀为包含全网 50% 以上节点的“巨型前沿”。此时若继续采用 Push 模式：
- 几乎全网所有边的两端都在活跃前沿周围，系统将产生上百亿次冗余的边遍历。
- 大量线程疯狂对未访问节点执行 `compare_and_swap`，多核原子操作的硬件开销暴增数十倍。

### Scott Beamer 的 Pull 遍历突破

Beamer 等人在 2012 年提出了反向拉取机制（Pull / Bottom-Up）：
- **转守为攻**：不以前沿为主语，而是遍历所有**尚未被访问的节点 $v$**。
- **反向探测入边**：节点 $v$ 逐一检查其入边邻居 $u \in N^-(v)$；只要发现**任意一个**邻居 $u$ 位于当前活跃前沿中，节点 $v$ 即可直接确立自己的父节点为 $u$，将自身状态标记为已访问，并**立刻提前终止对剩余邻居的遍历（Early Break）**！
- **完全消除原子锁**：在 Pull 模式下，每个未访问节点 $v$ 仅由单一工作线程负责处理，写入操作完全是私有本地的，读取前沿位图是只读且缓存友好的，彻底消除了跨核 CAS 写入竞争！

### Ligra 中的自适应双向切换

Ligra 将 Beamer 的洞见泛化为 `edgeMap` 内部的透明动态调度：
1. 算法计算当前活跃前沿 $U$ 的外向出边总数 $\text{deg}(U)$。
2. 若 $\text{deg}(U) + |E| / 20 > |E|$（即前沿包含边数超过阈值），Ligra 自动将计算编译为并行的 Pull 模式，直接并行扫描全图节点的入边位图。
3. 随着图遍历进入尾声，活跃前沿急剧收缩，Ligra 再次自动无缝切回稀疏的 Push 模式。

在 40 核单机服务器上，结合这一优化，Ligra 处理拥有数十亿条边的 Twitter 图只需几百毫秒，性能超越了当时由数百台机器组成的分布式集群！

::: insight 软硬协同的视角反转：主动出击不如静默守株
Push 与 Pull 的对偶性展现了算法工程中最深刻的系统辩证法：在图遍历的初始与收尾阶段，活跃前沿极度稀疏，此时“主动出击”（Push）能够以最小代价精准命中目标；而在前沿充斥全网的洪峰阶段，主动出击会导致数亿次重复碰撞，此时“静默守株”（Pull）反而展现出降维打击的威力。更精妙的是提前终止（Early Break）带来的剪枝奇迹——对于高度数节点，只需读到第一条来自前沿的边即可退场，将原本繁重的工作量化于无形。这种根据数据密度动态倒置因果执行方向的思想，是整个现代数据系统架构设计的基石。
:::
