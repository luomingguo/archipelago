# Lec 5 模板计算与时空分块优化（Stencil Computations & Cache-Oblivious Tiling）

## TL;DR

- **模板计算（Stencil）的算术强度困境**：模板计算在离散网格上根据局部邻居状态迭代推进时间步，朴素实现受制于微小的计算/访存比（Operational Intensity），极易撞上内存带宽墙。
- **时空分块（Spacetime Tiling）的核心机理**：打破单纯在空间维度切分的传统限制，将时间维度 $T$ 与空间维度 $X$ 联合构成分割块，利用因果锥（Dependency Cone）在数据常驻缓存期间连续推进多个时间步。
- **缓存无关梯形递归切分（Trapezoidal Decomposition）**：Frigo 与 Strumpen 提出的梯形切分算法，无需获知缓存尺寸即可递归切出斜率为因果边界的时空梯形，在多级存储上自适应达成最优缓存缺失率。

## 模板计算的形式化与内存瓶颈

模板计算是科学计算、地球物理模拟、流体力学以及图像处理中最为基础的计算模式之一。

在典型的一维或多维网格中，网格点在时间步 $t+1$ 的值由其在时间步 $t$ 时自身及几何临近的邻居点根据固定权重计算得出：
$$
A[t+1][x] = f(A[t][x-1], A[t][x], A[t][x+1])
$$

```text
Time t+1:             o (x, t+1)
                    / | \
Time t:      o (x-1)  o (x)  o (x+1)   <── 3 点依赖因果模板
```

### 朴素实现为什么极度缓慢？

朴素的双重循环实现如下：
```c
for (int t = 0; t < T; t++) {
    for (int x = 1; x < N - 1; x++) {
        B[x] = 0.25 * (A[x-1] + 2.0 * A[x] + A[x+1]);
    }
    // 拷贝回 A 或交换指针
    swap(A, B);
}
```
当空间网格规模 $N$ 远大于处理器缓存容量 $M$ 时，每推进一个时间步 $t$，CPU 都必须将整个大小为 $N$ 的数组从主存重新读入缓存，并将更新结果写回主存。
- **算术强度（Operational Intensity）**：计算一个点只需大约 3 次浮点操作，但至少需要传输一次缓存行。算术强度不到 $0.5 \text{ FLOP/Byte}$。
- 在现代 CPU 上，计算峰值可达数百 GFLOPs，但内存带宽仅有数十 GB/s。根据 Roofline 模型，朴素模板计算深深陷入**内存带宽受限（Memory-Bound）**区域，90% 以上的硬件计算单元处于空转饥饿状态。

## 时空分块（Spacetime Tiling）机制

解决模板计算访存受限的关键在于**复用时间局部性**：既然数据已经被加载到缓存中，我们为什么不能在缓存中一口气将数据推进 $K$ 个时间步，然后再写回主存？

直接对循环进行分块会遇到**数据因果依赖屏障**：由于 $A[t+1][x]$ 依赖 $A[t][x+1]$，如果在空间上切出一个垂直的长方形块，长方形边缘的点在向前推进时间步时，必须依赖相邻长方形未更新的数据，从而产生数据依赖冲突。

为了在推进时间的同时保持因果合法性，分块的几何形状必须由矩形扭曲为**平行四边形或梯形（Trapezoids）**，分块边缘的斜率必须与数据依赖传播的速度（光锥 / 因果锥）完全吻合。

## 缓存无关时空梯形切分（Frigo-Strumpen 算法）

Frigo 与 Strumpen 提出了完全摆脱对缓存大小 $M$ 依赖的**缓存无关梯形切分算法**。

在 $X \times T$ 的二维时空平面中，一个典型的计算区域被定义为一个下底宽、上底窄的梯形：
- 下底时间 $t_0$，空间区间 $[x_0, x_1]$；
- 上底时间 $t_1$，空间区间 $[x_0 + (t_1 - t_0), x_1 - (t_1 - t_0)]$。
由于内缩的斜率为 1，梯形内部的任意点在时间推进时的全部前驱邻居，均完全包含在该梯形的前序横截面内！这意味着**梯形内部的计算完全自治，不依赖任何外部数据更新**。

```text
Time t1:         ┌───────────────┐  上底 (空间收缩)
                /                 \
               /   因果自治梯形    \  斜率 = 依赖传播斜率
              /                     \
Time t0:     └───────────────────────┘  下底 (初始空间)
```

### 递归切分策略

算法在时空平面上交替执行两种递归切分：
1. **时间维切分（Cut-Time）**：当时间步长跨度较大时，在时间轴中点 $t_{\text{mid}} = (t_0 + t_1)/2$ 处横向一切为二，先递归执行下半部梯形，再递归执行上半部梯形。
2. **空间维切分（Cut-Space）**：当空间跨度远大于时间跨度时，沿空间轴垂直切分，将一个大梯形拆分为两个子梯形与一个倒三角（Triangle），按照严格的拓扑偏序递归执行。

```text
        ┌──────────────┐           ┌──────┬──────┐
        │              │  切空间   │ 子梯 │ 子梯 │
        │              │ ───────>  │ 形 1 │ 形 2 │
        └──────────────┘           └──────┴──────┘
```

**缓存收益分析**：
递归切分不断细化，直到子梯形的物理占有空间 $O(\text{Base} \times \Delta t) \le M$。此时，整个梯形被完整载入 L1/L2 缓存。CPU 可以在纯缓存内将这批数据无中断地推进 $\Delta t = \Theta(M)$ 个时间步！
- 总 I/O 复杂度从朴素实现的 $\Theta(N \cdot T / B)$ 剧减为：
$$
Q(N, T) = O\left(1 + \frac{N \cdot T}{B \cdot M^{1/d}}\right)
$$
其中 $d$ 为空间网格的维度。在多核并行与深层分层缓存中，梯形分块使算术强度直接提升了 $M^{1/d}$ 倍，彻底挣脱了内存带宽墙的束缚。

## Pochoir 编译器与前沿实现

将复杂的时空梯形手动用 C/C++ 递归函数实现极其繁琐易错。MIT 研发的 **Pochoir 编译器**通过嵌入式领域专用语言（DSL），允许用户仅需用自然数组语法声明模板函数，Pochoir 编译器自动生成包含缓存无关梯形切分、SIMD AVX 向量化与基于 Cilk 动态工作窃取调度的极端优化代码，在多核处理器上达成数十倍的端到端加速。
