# Lec 4 Cilk 运行时与工作窃取调度（Cilk Runtime System & Work-Stealing Scheduling）

## TL;DR

- **Cilk 语言的串行语义等价性（Serial Elision）**：去除程序中的 `cilk_spawn` 与 `cilk_sync` 关键字后得到的纯串行 C/C++ 程序，在语义上与并行版本完全等价，提供了极致的调试便利性。
- **双端队列（Deque）与非对称工作窃取**：每个 Worker 线程维护一个私有双端队列，本地线程在队列底部以 LIFO（后进先出，如同调用栈）压入和执行任务以最大化缓存局部性；空闲窃取者随机挑选受害者，从队列顶部以 FIFO（先进先出）窃取最大颗粒度的根部子树。
- **Blumofe-Leiserson 时空理论界限**：工作窃取调度器在 $P$ 个处理器上的期望运行时间严格满足 $\mathbb{E}[T_P] \le T_1/P + O(T_\infty)$，且执行所需的总栈空间严格受限于 $S_P \le P \cdot S_1$。

## Cilk 哲学与串行语义等价性

在传统的 pthread 或 OpenMP 显式线程编程中，程序员必须手动管理线程生命周期、处理线程池分配并显式绑定任务。这种方式将算法的逻辑结构与具体的物理执行硬件紧密耦合，导致程序极难调试且缺乏性能可移植性。

由 MIT Charles E. Leiserson 团队开发的 **Cilk 语言**（后衍生为 Cilk++, Intel Cilk Plus 以及 OpenCilk）提出了优雅的**语言级动态多线程范式**。Cilk 仅引入了三个核心关键字：
1. `cilk_spawn`：声明随后的函数调用可以与当前调用者并发异步执行，无需等待其返回。
2. `cilk_sync`：声明当前函数必须阻塞等待所有由此函数直接衍生的子任务全部执行完毕，形成同步屏障。
3. `cilk_for`：声明循环迭代之间无数据依赖，可以并发并行执行。

::: definition 串行投影 / 串行省略（Serial Elision）
对于任意合法的 Cilk 程序，若将其源码中的所有 `cilk_spawn` 和 `cilk_sync` 关键字宏替换为空白，将 `cilk_for` 替换为普通的 `for` 循环，所得到的纯串行 C/C++ 代码称为该并行程序的**串行投影（Serial Elision）**。一个正确且无竞态的 Cilk 程序的串行投影必须产出与并行执行完全相同的计算结果。
:::

## 双端队列与工作窃取算法

Cilk 运行时系统采用经典的**工作窃取调度器（Work-Stealing Scheduler）**，在用户态将海量细粒度动态任务映射到 $P$ 个物理操作系统工作线程（Worker Threads）上。

### 双端队列（Deque）机制

每个 Worker 拥有一个双端队列（Double-Ended Queue, Deque），队列中存储着挂起的计算帧（Activation Frames）：

```text
            (顶部 Top)  <── 窃取者 (Thief) 从顶部 FIFO 窃取大颗粒任务
           ┌──────────┐
           │ Frame 0  │  (浅层调用：子树规模大)
           ├──────────┤
           │ Frame 1  │
           ├──────────┤
           │ Frame 2  │  (深层调用：子树规模小)
           └──────────┘
           (底部 Bottom) <── 本地工作线程 (Worker) 在底部 LIFO 压入/弹出
```

- **本地操作（LIFO, 类似调用栈）**：本地 Worker 总是从队列底部（Bottom）推进执行。当遇到 `cilk_spawn` 时，将当前上下文作为新帧压入底部，并优先继续执行子调用（Spawn-Child 策略）。这一设计使得本地线程的行为模式与普通的串行深度优先搜索（DFS）完全一致，天然保证了对当前 CPU 缓存中热数据的极致复用。
- **远程窃取（FIFO, 抢占粗粒度树根）**：当某个 Worker 运行至 `cilk_sync` 且队列清空时，该 Worker 变为**窃取者（Thief）**。窃取者在系统中伪随机均匀选择另一个 Worker 作为**受害者（Victim）**，并尝试从受害者 Deque 的**顶部（Top）**窃取一个帧。

::: theorem 窃取顶部任务的深层机制
为什么窃取者必须从 Deque 顶部窃取？因为位于顶部的帧是在调用链最早期被放入的，对应于展开计算 DAG 中最靠近根节点的子树。从顶部窃取保证了窃取者一次性捕获了潜在工作量最大的大颗粒度任务，极大地摊销了跨核通信与锁同步的开销，避免了微小碎片任务的频繁跨核迁移。
:::

## Blumofe-Leiserson 时空理论界限

在 1999 年的经典论文中，Robert Blumofe 与 Charles Leiserson 运用势能分析法（Potential Method）给出了随机化工作窃取算法的严格数学保证。

::: theorem 工作窃取时间与空间理论界限
对于任意总工作量为 $T_1$、跨度为 $T_\infty$、单核串行栈空间为 $S_1$ 的动态多线程程序，采用基于随机化工作窃取调度器在 $P$ 个处理器上执行时，满足：
1. **期望时间界限**：
   $$
   \mathbb{E}[T_P] \le \frac{T_1}{P} + O(T_\infty)
   $$
2. **总窃取尝试次数**：执行过程中所有处理器发起的总窃取尝试次数在期望意义下为 $O(P \cdot T_\infty)$。
3. **严格栈空间界限**：全部 $P$ 个处理器所消耗的总内存调用栈空间满足：
   $$
   S_P \le P \cdot S_1
   $$
:::

**空间界限的工程意义**：
在许多朴素的线程池实现中，如果不加约束地生成任务，内存消耗可能会随着并行任务的泛滥而暴增至 $O(P \cdot T_1)$，导致系统发生 Out-Of-Memory 崩溃。Cilk 的 $S_P \le P \cdot S_1$ 空间界限保证了：只要单核能跑得下的程序，在 $P$ 核机器上至多只多消耗 $P$ 倍的栈内存，为大规模并发提供了坚实的资源安全边界。

::: pitfall 伪共享与 Deque 同步开销
在早期的双端队列实现中，如果顶部指针 `top` 和底部指针 `bottom` 位于同一个 64 字节的缓存行内，本地 Worker 的高频读写将导致远程窃取者不断使该缓存行失效，产生严重的**伪共享（False Sharing）**。工业级 Cilk 运行时（如 Cilk-5 提出的 THE 协议）通过强制内存对其填充（Padding），并精心设计无锁/单锁 Dekker 式轻量同步原语，使得本地 Worker 在绝大多数情况下无需获取全局锁即可完成压栈与出栈。
:::

::: insight 工作窃取的优雅对偶：以忙碌者的专注换取闲散者的自律
工作窃取调度的哲学美感在于其极致的非对称性。在现代操作系统中，绝大多数并发调度框架往往由“工作产生者主动将任务派发给工作消费者”，这种自顶向下的派发在任务极度碎片化时会产生毁灭性的通信雪崩。而工作窃取将通信开销完全转移给了“空闲的窃取者”：只要本地 Worker 还有任务，它就完全沉浸在本地的 LIFO 栈内高效推进，不受任何外部干扰；只有当某个核心真正闲置无所事事时，它才走出家门去随机窃取。这意味着**系统越忙碌，协调开销反而越趋近于零**，完美达成了自适应负载均衡的终极理想。
:::
