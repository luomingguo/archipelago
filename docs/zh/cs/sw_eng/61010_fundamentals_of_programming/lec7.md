# Lec 7 递归回溯搜索（Recursive Backtracking）

> 参考资料：[Recursive Backtracking](https://py.mit.edu/fall26/readings/backtracking)

## TL;DR

- **回溯的核心范式**：回溯法是系统性遍历庞大指数级决策空间的通用解法。通过“试探选择 $\to$ 递归推进 $\to$ 遭遇死胡同 $\to$ 撤销选择恢复现场”，实现对潜在解树的深度优先探索。
- **剪枝（Pruning）决定成败**：一旦当前部分候选解已经违反硬性约束，立即终止向下探索并直接返回（剪枝），防止在确定无解的庞大子树中浪费算力。
- **状态维护的性能抉择**：相比于在每一步递归中深拷贝整个局面状态（耗费内存与时间），**原地修改并显式撤销（In-place Mutation & Undo）**能在 $O(1)$ 常数时间内完成状态转移，是工业级求解器的标配模式。
- **启发式加速（MRV）**：优先处理可选候选项最少、约束最严苛的变量（Minimum Remaining Values），能在搜索树顶层极早触发剪枝，大幅压缩搜索规模。

## 什么是回溯搜索：从盲目试错到系统性剪枝

在计算机求解实际问题时，许多任务属于**约束满足问题（Constraint Satisfaction Problems, CSP）**或组合优化问题，例如数独游戏、八皇后谜题、布尔可满足性（SAT）、日程排课以及背包问题。这类问题的共同特征是：解空间随着变量数量呈指数级（$O(2^n)$ 甚至 $O(n!)$）爆炸，无法使用简单的多项式循环直接穷举。

回溯法（Backtracking）是一种**带有剪枝机制的系统性试错算法**。与无脑穷举所有叶子节点不同，回溯法在沿着决策树自顶向下尝试构建解的过程中，时刻检查当前部分解是否仍然有希望演变为合法解。

在计算复杂性理论中，许多组合优化问题被证明是 NP 完全（NP-Complete）问题。这意味着在目前的人类认知中，不存在已知且确定能够在多项式时间（如 $O(n^2)$ 或 $O(n^3)$）内彻底求解的最优算法。面对包含数十个布尔开关或上百个网格槽位的系统，整棵潜在的状态决策树所包含的叶子节点数量轻易超越宇宙中的原子总数。盲目穷举在物理现实面前是完全行不通的。

回溯算法的核心威力，在于将原本各自独立的孤立尝试，重新编织成一棵层次分明的“假设检验树”。每当我们做出一步决策，便立即评估该决策是否与已知的硬性约束冲突。一旦发现冲突，整个子树中数以亿计的排列组合就可以在千分之一毫秒内被整块“剪枝”（Pruning）抛弃，从而在指数级的荒原中迅速锁定生路。

```text
                     [根节点: 初始空白状态]
                    /                     \
            选择 1 (合法)                选择 2 (冲突) ──► [立即剪枝!]
             /          \                                 (无需探索庞大子树)
       选择 1.1        选择 1.2 (死胡同)
        (继续深入)         │
                     [撤销 1.2 恢复现场]
                           │
                      [尝试 1.3 ...]
```

### 磁带录音问题（The Mixtape Problem）

为了建立对回溯的直觉，考虑一个具象的问题：你有一张总容量严格为 $T$ 分钟的磁带，以及一组时长各异的候选歌曲列表。目标是找出恰好能够填满磁带容量 $T$ 的一组歌曲组合。

对每一首歌曲而言，我们面临一个二叉选择：**要么将该歌曲收录进磁带，要么跳过该歌曲**。

```python
def find_mixtape(target_time, songs):
    """
    寻找能够恰好填满 target_time 的一组歌曲时长元组。

    参数:
        target_time: 目标剩余时长 (int)
        songs: 候选歌曲时长元组 (如 (5, 3, 7, 2))

    返回:
        成功填满的歌曲元组，若无解返回 None
    """
    # 基准情形 1：目标时间刚好减为 0，成功找到完美解！
    if target_time == 0:
        return ()

    # 关键剪枝：目标时间已经透支变为负数，或者歌曲已耗尽，此路不通！
    if target_time < 0 or not songs:
        return None

    first_song = songs[0]
    rest_songs = songs[1:]

    # 分支一：尝试收录第一首歌
    # 递归子问题：在剩余歌曲中填满 (target_time - first_song)
    solution_with_first = find_mixtape(target_time - first_song, rest_songs)
    if solution_with_first is not None:
        return (first_song,) + solution_with_first

    # 分支二：如果包含第一首歌无解，回溯并尝试跳过第一首歌
    return find_mixtape(target_time, rest_songs)
```

注意上面代码中的 `if target_time < 0:`。如果当前累加的歌曲时长已经超过了磁带容量，函数立即返回 `None`。这一行简单的判断截断了整整一个半球的分支探索，这就是**剪枝（Pruning）**的巨大威力。

磁带录音问题在算法理论中有一个更为著名的学名——**子集和问题（Subset Sum Problem）**，它是经典的 0/1 背包问题的精确子集形态。

在这段代码的设计中，我们精妙地复用了递归的天然回退特性：
- 当代码执行 `solution_with_first = find_mixtape(...)` 并得到非 `None` 的解时，我们立即层层上报并成功返回，这被称为“早停成功”（Early Stopping）；
- 而当包含第一首歌的所有排列组合被内层递归证明全部死胡同（返回 `None`）时，程序控制流自然而然地滑落至第二行，开始试探“跳过第一首歌”的备选分支。整个回退机制由编程语言的调用栈自动驱动，无需编写繁琐的状态机跳转。

## Python 经典陷阱：可变默认参数

在编写回溯算法时，开发者经常需要一个容器来累积探索路径或记录当前状态。初学者常写出如下代码：

```python
# 严重反模式：可变默认参数！
def backtrack_solve(state, current_path=[]):
    current_path.append(state)
    ...
```

::: pitfall 默认可变参数的跨调用污染
在 Python 中，函数头部的默认参数表达式**仅在模块加载定义函数时求值一次**，并在内存堆中持久存在。当后续多次调用 `backtrack_solve` 且不传第二个参数时，所有调用都会共享同一个列表对象！上一轮探索的残留数据会直接污染下一轮独立搜索，引发极其隐蔽的幽灵 Bug。

**标准工程范式**：
1. 采用不可变元组传参：`current_path = current_path + (state,)`；
2. 或者使用 `None` 作为默认哨兵值：
   ```python
   def backtrack_solve(state, current_path=None):
       if current_path is None:
           current_path = []
   ```
:::

## 经典案例演练：数独（Sudoku）求解器

数独是一个标准的 $9 \times 9$ 约束满足网格。游戏规则规定：在每一个空格填入数字 1 到 9，使得每一行、每一列以及九个独立的 $3 \times 3$ 宫格内，数字 1 到 9 恰好出现一次且不重复。

```text
数独棋盘坐标与 3x3 宫格划分：
     Col: 0  1  2   3  4  5   6  7  8
Row 0:  [ .  .  . │ .  .  . │ .  .  . ]
Row 1:  [ .  5  . │ .  7  . │ .  1  . ]  Block (0, 0) ~ Block (2, 2)
Row 2:  [ .  .  . │ .  .  . │ .  .  . ]
       ───────────┼───────────┼───────────
Row 3:  [ ... ]
```

### 棋盘约束检验函数

在进入搜索循环之前，我们必须构建一个极度严谨的“裁判模块”。在指定的行 `row` 与列 `col` 尝试填入候选数字 `val` 时，该辅助函数必须能够在极短的时间内裁定该步是否合法。

在坐标定位上，将行号与列号映射到其所属的 $3 	imes 3$ 小宫格起点坐标，采用了优美的整数地板除与相乘技巧：
$$	ext{start\_row} = (	ext{row} // 3) 	imes 3, \quad 	ext{start\_col} = (	ext{col} // 3) 	imes 3$$
这一公式能够将任意落在 $[0, 2]$ 的索引映射到 0，$[3, 5]$ 映射到 3，$[6, 8]$ 映射到 6，从而精准定位当前宫格的左上角锚点。

```python
def is_valid_sudoku_move(board, row, col, val):
    """
    检查在 board[row][col] 处填入数字 val 是否符合数独规则。
    board 为 9x9 的二维列表，0 表示空格。
    """
    # 检查行约束：同行不能有重复数字
    if any(board[row][c] == val for c in range(9)):
        return False

    # 检查列约束：同列不能有重复数字
    if any(board[r][col] == val for r in range(9)):
        return False

    # 检查 3x3 宫格约束：定位当前宫格左上角起点
    start_row = (row // 3) * 3
    start_col = (col // 3) * 3
    for r in range(start_row, start_row + 3):
        for c in range(start_col, start_col + 3):
            if board[r][c] == val:
                return False

    return True
```

由于棋盘大小固定为 $9 	imes 9$，行检查遍历 9 次，列检查遍历 9 次，宫格检查遍历 9 次，整体单次校验的时间复杂度严格为 $O(1)$ 常数时间，不会随空格数量增加而产生膨胀。

### 原地修改与回溯撤销（Mutation & Undo）

实现数独求解器时，有两种处理局面状态的流派：
1. **纯函数拷贝派**：每次尝试填入一个数字，都深拷贝一份完整的 $9 \times 9$ 棋盘（耗时 $O(81)$ 且频繁触发垃圾回收）；
2. **原地修改撤销派（In-place Mutation）**：直接在原棋盘列表上将空格置为 `val` 并递归；若内层无解，**立即将该格重新置回 0 恢复现场（Undo）**！

原地修改撤销的状态转移耗时仅为 $O(1)$，内存开销为常数，是解决高频复杂搜索的黄金法则。

为了理解这一决策的深远影响，不妨对比一下二者的资源开销：
- **深拷贝方案**：如果每进入一层递归都执行 `[row[:] for row in board]` 复制棋盘，每次调用需分配 81 个单元格的新内存。搜索 100,000 次将产生数百万个短命列表对象，触发严重的垃圾回收停顿（GC Pauses）；
- **原地修改方案**：全局自始至终只维护唯一一个共享棋盘。在向下探索前赋值 `board[r][c] = val`，在失败回溯后执行赋值 `board[r][c] = 0`。整个转移只有两次寻常的数组写入，单步开销仅需几个 CPU 时钟周期。

完整的求解器实现如下：

```python
def find_empty_cell(board):
    """在数独网格中寻找下一个空格坐标 (row, col)，若无空格返回 None。"""
    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:
                return r, c
    return None

def solve_sudoku(board):
    """
    递归回溯求解数独。
    直接在传入的 board 上原地求解，若有解返回 True，若无解返回 False。
    """
    empty = find_empty_cell(board)
    # 基准情形：没有空格了，说明全部格子已合法填满，成功找到终极解！
    if empty is None:
        return True

    row, col = empty

    # 针对当前空格，依次试探数字 1 到 9
    for val in range(1, 10):
        # 剪枝检查：只有满足数独约束的数字才尝试深入
        if is_valid_sudoku_move(board, row, col, val):
            # 步骤 1: 试探性做出选择（原地修改）
            board[row][col] = val

            # 步骤 2: 递归推进，尝试求解后续的子局面
            if solve_sudoku(board):
                return True  # 内层找到了完整解，一路向上传递成功信号

            # 步骤 3: 核心回溯！说明填入 val 最终导致后续死胡同，撤销选择，恢复现场
            board[row][col] = 0

    # 尝试了 1 到 9 全都不行，触发回溯，向父节点返回无解
    return False
```

注意观察“选择”与“撤销”的对称性结构：`board[row][col] = val` 紧随其后的是递归调用，而在递归调用未能返回 `True` 的分支上，必定执行 `board[row][col] = 0`。这种犹如事务回滚（Transaction Rollback）的机制，确保了当程序回退到上层调用时，棋盘状态毫无偏差地维持在尝试当次选择之前的原始面貌。

## 回溯性能飞跃：启发式策略与约束传播

上述基础版回溯能够解决简单数独，但面对高难度“数独恶魔题”时，基础遍历仍可能耗费数秒甚至超时。我们可以通过引入启发式策略实现数量级的性能暴增。

### 最少剩余值启发式（MRV / Most Constrained Variable）

在 `find_empty_cell` 中，基础版本只是简单地从左到右、从上到下挑选遇到的第一个空格。

**最少剩余值启发式（MRV）**主张：**优先选择合法候选数字最少的格子进行试探**！
- 如果某个格子当前根据规则只能填唯一的一个数字（候选数数量为 1），那么先填它绝不会增加分支因子；
- 如果某个格子因为周围约束导致候选数数量为 0（死胡同），优先检查它能够**立即引发整场搜索的剪枝**，避免在其他无关格子上做上万次无用试探。

只需将选择格子的逻辑优化为“寻找具有最小候选集合的格子”，数独求解器的运行速度通常能直接提升数百倍。

### 贯通布尔可满足性（SAT）求解器

数独问题在数学上与计算机科学的基石问题——**布尔可满足性问题（SAT）**完全等价：
- 数独的每个位置对应布尔变量 $x_{r, c, v}$（表示行 $r$ 列 $c$ 填入数字 $v$）；
- 数独的行、列、宫格排他性对应合取范式（CNF）中的逻辑子句（Clauses）；
- 回溯法结合 MRV 与单元传播（Unit Propagation），正是现代工业级 SAT 求解器（DPLL 算法）的核心支柱。在随后的课程实验中，你将亲手构建完整的 SAT 求解器来自动化通关推箱子与拼图游戏。

## 我的理解与工程洞察

::: insight 搜索的艺术：在无限可能中用约束铸就确定性
回溯法是人类面对 NP 完全问题与不可逾越的组合爆炸时最强有力的反击。

在系统架构与算法工程中，应用回溯需要内化三条军规：
1. **撤销操作的对称性**：原地修改必须与撤销操作严格成对出现（宛如 C++ 中的构造与析构、操作系统的获取锁与释放锁）。任何分支提前退出（如遗漏恢复现场的 `return False`）都会永久污染全局局面；
2. **尽早失败原则（Fail-First Principle）**：在决策树的所有可选项中，**永远优先测试最容易失败的强约束变量**。在树的第 1 层剪枝掉 90% 的子树，其收益是在第 10 层剪枝的数十亿倍；
3. **记忆化与状态哈希**：如果在回溯过程中不同决策路径会汇聚到完全相同的棋盘局面，应将局面哈希后存入记忆化缓存字典（Memoization），将重复的指数级子树计算退化为 $O(1)$ 的查表读取。
:::
