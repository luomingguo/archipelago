# Lec 1 执行环境模型（The Environment Model）

> 参考资料：[The Environment Model of Execution](https://py.mit.edu/fall26/readings/environment_model)

## TL;DR

- **堆栈分离模型**：变量名存储在帧（栈）中，实际数据（整数、字符串、列表等）全部分配在堆（Heap）中，变量通过箭头（引用）指向堆中对象。
- **引用传递而非拷贝**：赋值语句 `b = a` 只是创建了一个新的指向同名对象的引用，绝不会在内存中隐式复制对象本身。
- **可变性陷阱**：列表存储的是元素引用的容器。原地操作（如 `a[0] = 99`、`a.append(...)`、`a += b`）会直接改变堆中对象，导致所有共享引用的变量同步变化；而切片 `a[:]` 仅产生浅拷贝。
- **垃圾回收机制**：对象仅在其引用计数归零（没有任何箭头指向它）时被自动回收。

## 动机：为什么需要环境模型

考虑以下经典的 Python 作用域与循环变量绑定的面试题：

```python
functions = []
for i in range(5):
    def func(x):
        return x + i
    functions.append(func)

for f in functions:
    print(f(12))
```

初学者往往预期输出是 `12, 13, 14, 15, 16`，但实际运行结果却是清一色的 `16`：

```text
16
16
16
16
16
```

为什么会这样？如果只从代码字面表面去理解，很难洞悉其本质。我们需要一套能够精确刻画程序运行时计算机内部状态的图形化推演工具——**执行环境模型**（Environment Model，亦称内存图）。

## 内存图的核心组成：栈帧与堆空间

在 Python 执行过程中，内存逻辑上被划分为两个核心区域：

1. **栈帧（Frames）**：用于维护命名空间（当前正在执行的代码块可见的变量名与引用的映射）。初始状态下是**全局帧**（Global Frame，GF）。
2. **堆（Heap）**：实际存储所有数据对象（整数、浮点数、字符串、函数对象、列表等）的物理空间。

## 变量绑定、赋值与垃圾回收

考虑以下顺序执行的代码片段：

```python
x = 307
x = 308
y = x
y = 342
```

1. 执行 `x = 307` 时，堆中分配了整数对象 `307`，全局帧中创建变量名 `x` 并用箭头指向 `307`。
2. 执行 `x = 308` 时，堆中新建整数对象 `308`，`x` 的箭头重新指向 `308`。此时对象 `307` 失去了唯一的引用，进入孤立状态。
3. 执行 `y = x` 时，全局帧创建变量名 `y`，并将箭头指向 `x` 当前指向的同一个对象 `308`。
4. 执行 `y = 342` 时，`y` 重新指向新创建的对象 `342`。

![变量重新赋值与无引用对象的垃圾回收](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/665b93af95538.png)

### 引用计数与垃圾回收

当堆中一个对象的入度（指向它的箭头数）降为 0 时，意味着程序中没有任何变量或数据结构能够再触达该对象。Python 底层的垃圾回收器（Garbage Collector）会检测到引用计数为 0 并回收该对象占据的内存。

## 列表在内存中的表示与操作

在 Python 中，列表是一个连续的容器对象，但**列表内部并不直接内嵌数据对象，而是存储指向各个元素的引用**。

```python
mylist = [309, 310, "cat"]
```

如果列表元素本身也是变量，则该列表槽位与变量指向堆中的同一个对象：

```python
x = 311
mylist = [x, 312]
```

对于空列表 `x = []`，环境图通常在堆中绘制一个带有竖线标记的空容器框，表示其长度为 0：

### 索引访问与项赋值

执行 `mylist[0]` 时，Python 首先在全局帧中解析名称 `mylist`，沿着引用找到堆中的列表对象；接着读取索引 0 位置的引用箭头，访问目标整数对象 `309`。

![通过索引访问列表元素时引用箭头的追踪过程](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66c569a7a33fb.png)

由于列表是可变对象（mutable），我们可以原地修改列表某个索引槽位的引用箭头，而不需要创建新的列表对象。

### 切片与浅拷贝

切片操作 `x[start:stop:step]` 会创建一个**全新的列表容器**，但其内部复制的仅仅是**引用本身**，即所谓的**浅拷贝**（Shallow Copy）：

```python
x = [[9, 8], [7, 6, 5]]
y1 = x       # 别名：y1 与 x 指向完全相同的列表对象
y2 = x[:]    # 浅拷贝：y2 是全新列表，但内部元素仍指向子列表 [9, 8] 和 [7, 6, 5]
x[0] = 20    # 修改 x 顶层索引 0 的引用
x[1][0] = 30 # 修改嵌套子列表内部的元素
```

![浅拷贝列表产生的全新容器及共享内部元素引用](https://tc-1258979383.cos.ap-guangzhou.myqcloud.com/66c5924650b9c.png)

执行完 `x[1][0] = 30` 后的环境图状态：

```python

print(y2)  # 输出: [[9, 8], [30, 6, 5]] （顶层被隔离开，但内层共享）
```

### 元素的追加、插入与删除

- `list.append(val)`：在列表末尾直接开辟一个新槽位，指向 `val`。
- `list.extend(iterable)`：将可迭代对象中的每个元素引用逐个追加到原列表末尾。
- `list.insert(i, val)`：在索引 `i` 处插入新引用，后续元素向后位移。
- `list.pop(i)`：移除并返回索引 `i` 处的元素引用。
- `list.remove(val)`：按值线性查找匹配的第一个对象，并将其引用从列表中移除。

### 原地拼接（+=）与全新创建（+）

- `z = x + y`：在堆中分配一个长度为 `len(x) + len(y)` 的**新列表**，并将 `x` 与 `y` 的元素引用拷贝进来，原列表 `x` 与 `y` 保持不变。
- `x += y`：对列表而言，`+=` 会被解释为原地扩展（等价于 `x.extend(y)`），直接修改 `x` 指向的堆对象。如果其他变量也指向 `x`，它们将观察到这一变化。

## 不可变容器：元组的内存语义

元组（Tuple）是不可变序列（immutable sequence）。

```python
t1 = (1, 2, 3)
t2 = 1, 2, 3   # 逗号才是构建元组的决定性语法
t3 = (7,)      # 单元素元组必须带有尾随逗号；(7) 只是整数 7
t4 = ()        # 空元组
```

::: pitfall 元组的不可变性边界
元组的“不可变”仅指**其内部存储的引用箭头不能重新绑定或增减**。如果元组中包含可变对象（如列表），该列表内部的状态依然可以被修改：

```python
t = (1, [2, 3])
t[1].append(4)  # 合法！列表内部发生变化，但元组本身存储的引用地址未变
print(t)        # 输出: (1, [2, 3, 4])
```
:::

## 何时使用环境图

在日常开发中，我们不需要为每一行代码绘制环境图。环境图是一套**心智调试规范**：
- 当遇到复杂的嵌套数据结构变更产生难以解释的副作用时；
- 当遇到闭包与作用域变量迟绑定问题时；
- 当需要严格证明算法空间开销与指针共享安全性时。

手绘几幅环境图能帮助我们迅速穿透语法糖，洞悉内存真实的拓扑流转。

## 我的理解与工程洞察

::: insight 引用语义：Python 一切皆对象的本质
初学 Python 的开发者常误以为变量是一个“盒子”，赋值是将值装进盒子里。而在 Python 的真实世界中，**变量只是一张贴在对象上的便利贴（Label）**。

理解这一心智模型的最大收益是编写高质量的工程代码：
1. **警惕默认可变参数**：`def append_to(item, target=[])` 中，函数对象在定义期只创建一次默认列表，后续所有未传实参的调用都会共享并修改同一个堆对象；
2. **区分身份与相等（is vs ==）**：`==` 比较两个对象包含的值是否等价，而 `is` 检查两个引用是否指向内存中的同一个堆地址；
3. **函数式无副作用保障**：在编写处理复杂数据的工具函数时，优先采用只读变换或显式复制，避免在调用方不知情的情况下破坏外部数据结构。
:::
